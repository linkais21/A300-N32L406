# A300-406 下一版通信与诊断优化设计

## 目标

下一版同时处理三项已确认问题：

1. 修复并诊断 EC800M `QISEND`/JT808 注册发送链。
2. 发布构建自动刷新启动日志中的 Build 时间。
3. 增强 DA218E 供电、总线电平及 I2C 失败阶段诊断。

本轮不重写 EC800M 为全异步发送状态机，也不把 DA218E 改为软件 I2C；先用最小改动恢复发送并取得足够硬件证据。

## JT808 与 QISEND

### 当前证据

TCP 通道已进入 online，但设备持续打印 `[808] register`，没有进入源码中发送成功后的 `[808] register retry`。相邻日志约间隔 3 秒，与等待 `AT+QISEND` 提示符的超时一致，因此注册帧没有成功提交给模组。

### 设计

- 将 QISEND 分为 command、prompt、payload、result 四个明确阶段。
- 提示符 `>` 按单字节提示处理，不依赖 CR/LF 行结束。
- 发送前输出通道和帧长度；失败时只输出具体阶段和返回原因。
- 只有 payload 发出并收到 `SEND OK` 后，JT808 才进入 REGISTERING。
- 发送失败保持 IDLE，但增加有限退避，避免主循环连续阻塞和刷屏。
- 注册帧成功提交后，继续沿用现有 5 秒应答重试机制。
- 接收注册应答时记录通道、消息 ID、流水号和结果；不打印鉴权密钥。

## Build 时间

- 发布脚本在强制全量编译前生成 `include/build_version.h`。
- 时间统一由构建脚本生成，不再依赖工作区中旧的固定文件内容。
- 产物清单记录相同的 UTC build ID；启动日志继续显示便于现场核对的本地时间。
- 生成步骤失败时立即中止发布，禁止静默复用旧版本头。

## DA218E 诊断

- 保留当前兼容地址探测，不再增加猜测地址。
- 探测前读取 PB6/SCL、PB7/SDA 输入电平并打印一次。
- 每次探测记录首个失败阶段：总线空闲、START、写地址、寄存器、RESTART、读地址或数据。
- 同一失败原因做摘要，避免十二次探测产生过量日志。
- 诊断只观察现有硬件 I2C，不改变 PB6/GPS_EN 复用策略。
- 若 PB6/PB7 空闲不同时为高，或事务期间 GPS_VCC 掉电，后续结论转为硬件复用/供电问题，不继续改地址。

## 测试与验收

- 主机测试覆盖裸 `>` 提示符、`SEND OK`、prompt 超时、result 超时和 AT owner 释放。
- JT808 测试覆盖发送失败保持 IDLE、退避限流、发送成功进入 REGISTERING。
- 构建测试确认版本头刷新并实际编入 ELF。
- DA218E 契约测试确认电平与失败阶段日志存在，且所有等待均有界。
- 执行全量 APP、Bootloader 构建和现有发布包校验。
- 实机验收日志应出现新的 Build 时间，以及以下两类结果之一：
  - `[4G-TX] ch=0 ... SEND OK` 后收到 JT808 注册应答；
  - `[4G-TX] fail stage=...`，能明确定位模组发送链阶段。
- DA218E 日志应明确显示总线电平及首个失败阶段，或显示有效 Chip ID。

## 不在本轮范围

- 修改服务器地址、注册身份或平台配置。
- 重写 EC800M 整体驱动架构。
- 未经实测证据更换 I2C 引脚或改动 PCB 策略。
- 自动烧录实物设备。
