# I2C 与 EC800M 串口诊断优化设计

日期：2026-08-31

## 1. 目标

修复当前实机日志确认的两个软件问题，并提升调试构建通过串口快速定位故障的能力：

- N32L406 的 PD14/PD15 配置为 I2C2 时使用了错误的 AF1；芯片用户手册规定 PD14/PD15 的 I2C2 SDA/SCL 必须使用 AF6。
- EC800M 网络注册查询以 `+CEREG:` 或 `+CGREG:` 前缀作为 AT 事务完成条件，可能在状态数字尚未接收完整时提前返回，导致注册状态保持 `-1`。

本次不修改硬件引脚、DA218E 地址策略、网络注册超时策略、FOTA、JT808 或生产部署行为。

## 2. 编译控制

使用单一编译宏：

```c
A300_DIAG_VERBOSE
```

- 未定义时：发布/普通构建只保留状态变化、成功摘要和最终失败摘要。
- 定义时：增加 I2C 寄存器、引脚电平、事务阶段，以及经过脱敏和限长的 AT 命令/响应诊断。
- `A300_HARDWARE_BRINGUP` 构建默认同时启用 `A300_DIAG_VERBOSE`；普通构建不默认启用。

详细诊断不得改变状态机时序、重试次数、超时值或协议数据。

## 3. I2C/DA218E 修复与诊断

### 3.1 功能修复

`BSP_I2C_GPIO_AF` 从 `GPIO_AF1_I2C2` 改为 `GPIO_AF6_I2C2`。现有硬件引脚契约测试同步改为 AF6，并增加对 N32L406 PD14/PD15 映射的明确说明。

### 3.2 详细日志

调试构建在以下边界打印一行诊断：

- GPIO 输入模式读取总线电平。
- 切换为 AF6 并初始化 I2C2 后。
- 总线恢复前后。
- START、地址发送、寄存器发送、重复 START、接收地址和数据阶段失败时。

日志包含：阶段、地址、SCL/SDA、CTRL1、CTRL2、STS1、STS2、CLKCTRL。示例：

```text
[I2C-DIAG] phase=AF addr=-- SCL=1 SDA=1 C1=<hex16> C2=<hex16> S1=<hex16> S2=<hex16> CCR=<hex16>
[I2C-DIAG] phase=ADDR-R addr=0x26 SCL=1 SDA=1 C1=<hex16> C2=<hex16> S1=<hex16> S2=<hex16> CCR=<hex16>
```

普通构建只保留：

```text
[ACCEL] ready addr=0x26 id=0x13
[ACCEL] failed stage=ADDR-R addr=0x26 SCL=1 SDA=1
```

地址轮询仍覆盖 `0x26`、`0x27`、`0x13`、`0x14`，但 AF 修复后再由 CHIPID `0x13` 判定实际有效地址。

## 4. EC800M 网络注册修复与诊断

### 4.1 AT 完成边界

网络注册查询必须等待完整 AT 事务结束，再解析响应：

- 终止条件为完整的 `OK` 或 `ERROR` 行，而不是 `+CEREG:`/`+CGREG:` 前缀。
- 事务完成后，从缓冲区查找并解析 `+CEREG: <n>,<stat>`；失败时再查询 `+CGREG?`。
- 注册成功状态为 `1` 或 `5`；`0/2/3/4` 保留为真实状态，不得转换成 `-1`。
- 响应缺失、截断或格式非法时才使用 `-1`，并记录解析失败原因。

### 4.2 详细日志

详细日志输出命令、事务结束原因、响应长度、脱敏后的响应摘要和解析结果：

```text
[4G-AT] TX AT+CEREG?
[4G-AT] RX cmd=CEREG len=20 end=OK data="+CEREG: 0,2|OK"
[4G-NET] source=CEREG mode=0 stat=2
```

普通构建只在状态变化时输出：

```text
[4G] NETREG stat=2
[4G] ready
```

相同状态的周期查询不重复刷屏；原有十秒健康摘要继续保留。

## 5. 敏感信息与串口负载

- 原始响应单条日志限制最大长度，控制串口占用。
- 将 CR/LF 转换成可见分隔符，禁止输出不可控二进制数据。
- 不记录短信正文、短信号码、APN 用户名/密码、设备 Key、鉴权码、AGNSS 凭据或网络接收负载。
- IMEI、ICCID 沿用当前启动摘要；本次不扩大其输出范围。
- 仅允许白名单诊断命令输出响应摘要，例如 `AT`、`CIMI`、`CEREG?`、`CGREG?`、`QIACT?` 和 `CSQ`。敏感命令只打印命令类别，不打印参数。

## 6. 测试设计

先建立失败回归，再修改生产代码：

1. 硬件契约测试要求 PD14/PD15 使用 `GPIO_AF6_I2C2`，当前代码应先失败。
2. EC800M host-C 测试将响应拆成多个片段输入：`+CEREG:`、` 0,1`、`OK`，证明前缀到达时不能提前结束。
3. 覆盖 `stat=0..5`、漫游成功 `5`、截断响应、非法格式和 CEREG 到 CGREG 回退。
4. 源码契约测试确认详细日志位于 `A300_DIAG_VERBOSE` 条件编译中。
5. 普通构建与 `A300_HARDWARE_BRINGUP` 构建均需通过；检查 map/RAM 预算和 `git diff --check`。

## 7. 实机验收

修复后需要实机/HIL 验证：

- I2C2 初始化后 SCL/SDA 保持高电平，STS2 BUSY 清零。
- 至少一个候选地址读取 CHIPID `0x13`，并完成 DA218E 寄存器配置。
- EC800M 日志能显示真实注册状态；状态达到 `1` 或 `5` 后进入 PDP 和 READY。
- 分别测试详细日志开启和关闭的构建，确认关闭时无大量 AT 原始响应刷屏。
- 连续运行期间没有看门狗复位、串口阻塞或明显主循环延迟。

## 8. 非目标与剩余风险

- 本次不判断 DA218E 最终量产地址，只修复使地址探测能够真实执行的 AF 根因。
- 若 AF6 后总线电平正常但 CHIPID 仍失败，需要进一步检查器件供电、焊接、外部上拉和实际板级走线。
- 若 EC800M 能解析出 `0/2/3/4` 但长期无法进入 `1/5`，问题转为天线、SIM、信号或运营商网络，需要实机网络侧诊断。
