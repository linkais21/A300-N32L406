# 里程数学量化规则草案

状态：待产品规则确认，仅完成设计与边界评估；未应用到默认固件。用户要求继续推进数学方案，先明确阈值附近规则。本轮不涉及日志、不更改 Flash 格式或发布版本。

## 推荐契约

选择“受限 double 距离实现 + 统一毫米量化”作为下一阶段候选规范。不能把“替换距离算法”同时表述为“与旧 libm 每一个边界决策完全相同”。受限算法片段为 `tools/experiments/mileage_distance_bounded.inc`；实现、编译器选项及测试向量共同受版本管理。

1. 经纬度继续用 double，先做 double 差值，禁止改为 float 经纬度。有效定位标记以及坐标合法性校验通过后，才参与计算；无效、NaN、Inf 或负距离不累加、不更新上次有效基准，不把它们强制转成零距离。首次有效点只建立基准。
2. 对非负有限距离先限幅到 8192 米，再转为整数毫米：`d_mm = (uint32_t)(min(d_m, 8192.0) * 1000.0 + 0.5)`。正数采用最近整数，恰好半毫米向上；实现中的“恰好”指 binary64 运算结果，不宣称精确实数计算。最大 8192000 毫米，远小于 uint32 上限，必须先检查有效性/限幅再转换。
3. 防漂距离阈值使用 `threshold_mm = (uint32_t)stopdrift_thr * 100U`。保持当前 raw/10 米语义，不重新解释协议单位。raw=50 对应 5000 毫米，最大 raw=65535 对应 6553500 毫米。单位原文尚未确认，不能借本次量化迁移配置值。
4. 防漂启用、`speed_kmh < 2.0f` 且 `d_mm < threshold_mm` 时过滤，不推进位置基准。**等于阈值不按防漂过滤**。速度仍使用原有 float 比较，恰好 2.0 km/h 不进入低速过滤；本轮不量化速度。
5. 防漂通过后，仅当 **`500U < d_mm && d_mm < 1000000U`** 才调用里程累加。恰好 500 毫米和 1000000 毫米都不累加。
6. 本段里程增量是 **`delta_m = d_mm / 1000U`**，仍按整米逐段截断，不引入余数累计，不改变保存结构。例如 501～999 毫米虽然进入累加分支，但增量为 0；保留当前零增量调用的语义，不顺手改变 dirty/回调行为。
7. 防漂通过后，即使距离 <=500 毫米或 >=1000000 毫米而不累加，也按现有策略推进位置基准。相同坐标提前返回、持久化周期、失败退避与配置持久化代次保持原样。

距离截断 8192 米只服务现有里程策略：它高于 1000 米累加上限和 6553.5 米最大防漂阈值。不得用作围栏、导航或通用距离函数；若新增消费者或扩大参数范围，必须重新审查。

## 边界举例

以下是十进制理想值的规则说明，实际机器精度边界要按测试向量逐一验证。

| 输入距离 | 量化毫米 | 防漂关闭时的里程分支 / 增量 |
|---|---:|---|
| 0.4996 m | 500 | 不累加，推进基准 |
| 0.5004 m | 500 | 不累加，推进基准 |
| 0.5006 m | 501 | 调用累加，增量 0 m，推进基准 |
| 0.9996 m | 1000 | 增量 1 m |
| 1.0004 m | 1000 | 增量 1 m |
| 999.9994 m | 999999 | 增量 999 m |
| 999.9996 m | 1000000 | 不累加，推进基准 |
| 1000 m | 1000000 | 不累加，推进基准 |

防漂 raw=50、低速时，4.9994 m→4999 mm，过滤且保留旧基准；4.9996 m→5000 mm，等于阈值，继续后续判断。量化最大约半毫米的距离变化，并不意味着累计里程最多只差半毫米：在 1000 米拒绝边界可能造成一次 999 米增量有无的差别；基准推进变化还可能影响后续样本。

## 为什么不是“加 epsilon 就完全等价”

统一量化把原先整数米附近的舍入噪声收敛，但将不连续点移到了半毫米位置。任何离散比较仍有边界；任意添加 epsilon、模糊区或迟滞，也只会增加/移动边界，且可能引入新的状态规则。当前不建议为追求不可达的全输入旧实现等价而增加这些逻辑。

直接提高累加精度、保存毫米余数可改善逐段截断偏差，但会改变累计策略、RAM 与掉电语义；不属于本次体积优化，不捆绑实施。

## 实测依据及限制

执行：

```powershell
python tools/experiments/assess_mileage_quantization.py --replay build/mileage-bounded-replay-final-20260916 --output build/mileage-quantization-20260916
```

方法：复用前次编译的真实 C 基线和受限算法距离入口，核对源码一致性，对距离输出在 Python 中应用上述整数规则。新增半毫米边界样本实际运行两个 C 可执行程序，记录其 SHA256。**这不是新规则的生产 C 或 ARM 验证。**

| 数据集 | 样本数 | 两算法都采用新规则后的决策差异 | 新候选相对旧规则改变的样本 |
|---|---:|---:|---:|
| 原有点对回放 | 25128 | 0 | 1020 |
| 新增半毫米边界点对 | 756 | 26 | 323 |

差异统计比较整米增量、是否调用累加、是否推进基准；样本特意密集覆盖边界，不代表真实行驶差异比例。原先 51 个边界差异在原数据集消失，不代表算法已全域等价。新规则相对旧规则的 1020 个变化是明确的语义变化，不能隐藏为误差修正。

输出：`build/mileage-quantization-20260916/assessment.json`、半毫米样本及两个 C 入口输出。所有样本均为合成坐标。
