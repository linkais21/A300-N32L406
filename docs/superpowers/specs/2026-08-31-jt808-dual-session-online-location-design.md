# A300_406 JT808 双通道注册上线定位设计

日期：2026-08-31

## 1. 目标与范围

在 N32L406 目标固件中完成 JT/T 808-2013 注册、鉴权和定位上线闭环，同时修复阻断该闭环的 I2C2 与 EC800M 网络注册问题：

1. EC800M 完成网络注册状态解析、PDP 激活和 TCP 建链。
2. 主、备服务器分别建立独立 JT808 会话，完成 `0x0100 → 0x8100 → 0x0102 → 0x8001`。
3. 每个已鉴权通道独立接收实时 `0x0200` 定位上报。
4. 首次取得有效、可信时间的 GNSS 定位后立即上报，之后按配置周期上报。
5. 设备没有配置 PID 时，由合法 IMEI 派生稳定身份并持久化。

协议固定为 JT/T 808-2013，使用 12 位终端手机号对应的 6 字节 BCD 消息头。不得引入 JT/T 808-2019 的协议版本标识、20 位终端号或版本化消息头。

`D:\A300_Tools\A300-N32G452\A300-N32G452\app` 仅作为已量产 A300 行为参考。目标实现必须保留 N32L406 的现有模块边界，并满足 128 KiB Flash、24 KiB SRAM 预算；不得整体移植参考工程的大型 JT808、低功耗、RTC、定位完整性或其他无关模块。

## 2. 已确认产品决策

- 实现方式：在现有 N32L406 架构中增加轻量双通道 JT808 会话。
- 主、备服务器均独立注册、鉴权并接收定位，不采用主失败后才切备的单会话策略。
- 配置已有合法 11 位 PID 时保持不变。
- PID 为空且取得合法 15 位 IMEI 时，取 IMEI 末 11 位作为 PID 并持久化。
- 消息头终端手机号为 `0 + 11位PID`。
- `0x0100` 注册体终端 ID 为 PID 末 7 位。
- 尚未取得有效定位时，不使用零坐标、过期坐标或冻结坐标伪装有效定位。
- 鉴权成功且已有新鲜有效定位时立即发送 `0x0200`；否则等待首次有效定位后立即发送。

## 3. 架构与数据流

```text
EC800M 注网 → PDP 激活
       │
       ├─ TCP CH0（主）→ JT808 主会话：注册 → 鉴权 → ONLINE ─┐
       │                                                    ├→ 有效定位 0x0200
       └─ TCP CH3（备）→ JT808 备会话：注册 → 鉴权 → ONLINE ─┘
```

EC800M、TCP、JT808 和 GNSS 的责任边界保持如下：

- `ec800m.c`：AT 事务、注网/PDP 状态和模组 socket 收发。
- `tcp_manager.c`：两个 socket 的建链、断线检测、generation 和连接退避。
- `jt808.c`：每通道协议会话、帧编解码、注册/鉴权事务、定位发送策略。
- `terminal_identity.c`：PID/IMEI 校验、派生和 JT808 身份字段生成。
- `flash_config.c`：PID 和两个平台鉴权码的兼容持久化。
- `gps.c`：GNSS 数据、新鲜度和有效性；JT808 不绕过该接口猜测定位有效性。

两个会话共享不可变的终端身份和定位快照，但不共享可变的注册状态、鉴权码、请求流水号、TCP generation、重试计数或退避截止时间。

## 4. EC800M 与 I2C 阻断项

### 4.1 I2C2 复用修复

N32L406 的 PD14/PD15 用作 I2C2 SDA/SCL 时必须配置 `GPIO_AF6_I2C2`。当前 `GPIO_AF1_I2C2` 会在切换 AF 后使 SCL/SDA 同时为低且 I2C2 BUSY，必须改为 AF6，并同步引脚契约测试。

地址探测仍覆盖 `0x26`、`0x27`、`0x13` 和 `0x14`。AF 修复后以 CHIPID `0x13` 判断实际有效地址；不得根据 AF 错误期间的 BUS 失败确定量产地址。

### 4.2 网络注册 AT 完成边界

`AT+CEREG?` 和 `AT+CGREG?` 必须等待完整 AT 事务结束：

- 成功终止条件为完整 `OK` 行。
- 失败终止条件为完整 `ERROR` 行或超时。
- 事务完成后再解析 `+CEREG: <n>,<stat>` 或 `+CGREG: <n>,<stat>`。
- `stat=1` 和 `stat=5` 表示注册成功。
- `stat=0/2/3/4` 必须作为真实状态保留。
- 只有响应缺失、截断或格式非法时才使用 `-1`。

达到现有网络注册总超时后继续使用有界模组恢复，不引入无限复位。诊断日志记录命令类别、完成原因、响应长度和解析状态，不打印 IMEI、ICCID、鉴权码、短信内容或其他敏感值。

## 5. 终端身份与配置迁移

### 5.1 身份规则

合法 PID 必须正好为 11 位十进制数字。合法 IMEI 必须正好为 15 位十进制数字。

启动时按以下顺序获得身份：

1. 配置中存在合法 PID：直接使用，绝不自动覆盖。
2. PID 为空且 IMEI 合法：取 IMEI 末 11 位生成 PID，通过现有配置事务持久化一次。
3. PID 非空但非法，或 IMEI 不合法：禁止发送注册/鉴权/定位，限速输出身份错误，等待配置修复或模组身份可用。

PID 持久化失败时不得只在 RAM 中继续使用一个重启后会变化的身份。设备保留离线状态并按有界策略重试持久化。

JT808-2013 身份编码固定为：

- 消息头：`0 + PID`，共 12 位十进制数字，编码为 6 字节 BCD。
- 注册体终端 ID：PID 末 7 位，原样写入 7 字节字段。

### 5.2 注册体字段

`0x0100` 使用 JT/T 808-2013 表 7 格式：

- 省域 ID：`0`，由平台采用默认值。
- 市县域 ID：`0`，由平台采用默认值。
- 制造商 ID：沿用当前 A300 产品配置，固定 5 字节，不足补 `0x00`。
- 终端型号：沿用当前 A300 产品配置，固定 20 字节，不足补 `0x00`。
- 终端 ID：PID 末 7 位。
- 车牌颜色和车辆标识：沿用配置；未上牌时颜色为 `0`，车辆标识按平台建档契约处理。

所有字符串复制必须有边界检查，不允许注册体超过帧缓冲容量。

### 5.3 双鉴权码与配置兼容

配置持久化升级为主、备两个鉴权码：

- 旧配置中的单一 `auth_code` 迁移为主通道鉴权码。
- 备通道鉴权码初始为空，首次在备通道注册成功后保存。
- 当前 v2 只有 magic、版本、长度、A/B 双槽和 CRC，没有 generation 或最后提交标记。v3 必须新增 generation 和最后提交标记，并在启动时选择 generation 最新的完整有效槽。
- v3 写入只更新非当前槽：先擦除目标槽，写入头、数据和 CRC，验证成功后最后写提交标记；任何切点掉电都保留另一槽的最后有效配置。
- 旧格式必须保持可读；迁移中断或写入失败时不得损坏最后一份有效配置。
- 主、备鉴权码分别更新，单个通道的注册结果不得覆盖另一通道鉴权码。

鉴权码不得输出明文。日志只记录通道、消息 ID、流水号、结果码、状态变化和失败阶段。

## 6. 双通道 JT808 会话

### 6.1 会话数据

每个业务通道维护一个固定大小的静态 `jt808_session_t`，至少包含：

- 通道号。
- 当前 TCP generation。
- `IDLE/REGISTERING/AUTHENTICATING/ONLINE/BACKOFF` 状态。
- 最近一次注册流水号、发送时间和有效标志。
- 最近一次鉴权流水号、发送时间和有效标志。
- 注册与鉴权重试次数。
- 退避截止时间。
- 是否等待首次有效定位。
- 对应通道的鉴权码来源。

不得动态分配会话或帧缓冲。两个会话的新增静态 RAM 必须进入 map/RAM guard 检查。

### 6.2 状态转换

每个通道独立执行：

```text
TCP OPEN/generation 变化
        │
        ▼
      IDLE
        ├─ 无鉴权码 → 发送 0x0100 → REGISTERING
        └─ 有鉴权码 → 发送 0x0102 → AUTHENTICATING

REGISTERING --匹配且成功的 0x8100--> 保存本通道鉴权码
                                       │
                                       └→ 发送 0x0102 → AUTHENTICATING

AUTHENTICATING --匹配且成功的 0x8001--> ONLINE

重试耗尽 → BACKOFF --到期--> IDLE
TCP 断开/generation 变化 → 清理该通道未完成事务 → IDLE
```

注册和鉴权均采用 5 秒重试间隔，每轮最多 3 次有效发送尝试；耗尽后进入 60 秒退避。计数只在实际发送成功进入等待应答后递增，发送层立即失败不得伪装为已经发出。

鉴权连续失败或超时耗尽后，本通道的鉴权码视为可能过期：清除并持久化该通道鉴权码，退避结束后重新注册。另一通道的鉴权码和会话不受影响。

### 6.3 应答绑定

`0x8100` 只有同时满足以下条件才能推进状态：

- 接收通道与注册发送通道一致。
- 当前 TCP generation 与发送时一致。
- 应答流水号与该通道待处理注册流水号一致。
- 会话当前处于 `REGISTERING`。
- 帧校验、转义、消息体长度和终端身份均合法。

结果 `0` 表示成功并携带鉴权码；结果 `1–4` 为明确拒绝，必须记录结果并进入有界退避，不得按成功处理。

`0x8001` 对 `0x0102` 的应答只有同时满足通道、generation、应答流水号、原消息 ID 和结果码 `0` 时，才能使对应会话进入 `ONLINE`。旧连接、另一通道、重复或错流水号应答全部忽略。

### 6.4 发送路由

- 注册和鉴权只发到所属通道，不广播。
- 平台命令的通用应答发回命令来源通道。
- 周期定位分别发送到每个 `ONLINE` 通道。
- 心跳分别使用每个在线会话的定时器和通道。
- 盲区补传和其他现有业务默认保持当前所有权；本次只调整其在线判断和路由，使数据不发送到未鉴权通道，不扩大 Flash 布局或补传协议范围。

## 7. 定位上线行为

### 7.1 有效定位条件

实时 `0x0200` 只使用 GNSS 模块标记为有效且未超过现有新鲜度上限的数据。坐标、速度、方向、海拔、定位质量和时间必须来自同一可解释快照。

以下数据不得作为“已定位”实时上报：

- 零坐标占位。
- 超过新鲜度上限的坐标。
- 仅为静止防漂移而冻结的坐标，却把当前无定位状态标为有效。
- 无可信 BCD 时间的数据。

历史有效位置仍可用于现有盲区记录或明确标记的离线恢复路径，但不得冒充首次实时有效定位。

### 7.2 首次定位与周期定位

每个通道鉴权成功时：

1. 若当前已有新鲜有效定位和可信时间，立即向该通道发送一次 `0x0200`。
2. 否则设置该会话的“等待首次有效定位”标志，并先通过心跳维持在线。
3. GNSS 从无效变为有效时，向所有仍在等待且 `ONLINE` 的通道分别立即发送一次 `0x0200`。
4. 某通道发送成功后清除该通道等待标志；发送失败则保留以便有界重试。

周期定位只在至少一个通道 `ONLINE` 时执行。每次构建一个不可变定位快照和协议体，再分别封装/发送到在线通道，避免两个通道读取到不同瞬时数据。

`0x0200` 保留 JT/T 808-2013 基本字段：报警、状态、纬度、经度、海拔、速度、方向和 6 字节 BCD 时间；现有附加项只有在长度、单位和来源有效时保留。

### 7.3 发送失败和盲区

- 单通道发送失败不得阻止另一在线通道发送。
- 全部通道离线时继续使用现有盲区存储所有权和布局。
- 至少一个通道成功时，不得因另一通道失败重复追加同一个实时点到盲区。
- 是否消费盲区记录必须绑定到现有确认/重放事务，不能因为一个 socket 写入成功就提前删除。

## 8. 接收解析与安全边界

两个通道分别保留接收组帧状态，并绑定 TCP generation。解析必须覆盖：

- 半包、粘包和多帧连续输入。
- `0x7d 0x01`、`0x7d 0x02` 转义与非法转义。
- 最大帧长度和消息体长度一致性。
- XOR 校验失败。
- 重复包、旧 generation、错通道和错流水号。
- `0x8100` 鉴权码为空、过长或消息体截断。
- `0x8001` 原消息 ID、应答流水号和结果码不匹配。

任何无效帧只能影响其来源通道的诊断计数，不得改变会话、配置、继电器或其他业务状态。

## 9. 日志与可观测性

量产摘要日志应能证明完整链路而不泄露身份：

```text
[4G] NETREG stat=1
[4G] ready
[TCP] ch0 online gen=2
[808] ch0 REGISTER sn=10
[808] ch0 REGISTER_RESP sn=10 result=0
[808] ch0 AUTH sn=11
[808] ch0 ONLINE
[808] ch0 LOCATION sn=12 fixed=1
```

主、备通道分别记录状态变化。相同状态的周期轮询不得重复刷屏。IMEI、ICCID、PID、完整服务器凭据和鉴权码不得出现在新增日志中。

## 10. 测试设计

所有行为变更先建立失败回归，再写最小实现。

### 10.1 身份与配置

- 合法已有 PID 保持不变。
- PID 为空时从合法 IMEI 派生末 11 位并持久化。
- 非法 PID、短 IMEI、非数字 IMEI 和持久化失败拒绝上线。
- 消息头为 `0 + PID` 的 6 字节 BCD。
- 注册体终端 ID 为 PID 末 7 位，省市为 `0/0`。
- 旧单鉴权码配置迁移到主鉴权码，备鉴权码为空。
- 配置写入中断后仍可恢复最后一份有效配置。

### 10.2 EC800M 与 I2C

- 引脚契约要求 PD14/PD15 使用 `GPIO_AF6_I2C2`，并拒绝 AF1。
- `+CEREG:`、状态字段和 `OK` 分片到达时不得在前缀处提前完成。
- 覆盖 `stat=0..5`、CEREG 到 CGREG 回退、ERROR、截断和非法格式。
- I2C 总线恢复仍有界，所有等待有超时。

### 10.3 JT808 双会话

- 主、备同时从空鉴权码独立完成注册和鉴权。
- 一个通道已有鉴权码时直鉴权，另一个通道仍注册。
- `0x8100` 成功、结果 `1–4`、空鉴权码和超长鉴权码。
- `0x8001` 成功、拒绝、超时和原消息 ID 错误。
- 错通道、错流水号、重复响应和旧 TCP generation 不推进状态。
- 主通道断开不重置备通道，反之亦然。
- 每轮最多 3 次，之后 60 秒退避；退避期间不产生发送风暴。
- 旧鉴权码失效后只清除对应通道并重新注册。

### 10.4 定位

- 鉴权时已有有效定位，立即向该通道发送一次。
- 鉴权时无定位，首次有效定位后立即发送。
- 双通道先后鉴权时各自收到一次首次定位。
- 周期定位只发给已鉴权通道。
- 无定位、过期定位或无可信时间不发送伪造实时定位。
- 单通道发送失败不影响另一通道。
- 全离线时走现有盲区存储，部分在线时不重复落盘。
- 校验 `0x0200` 字段大小端、单位、BCD 时间、转义和 XOR。

## 11. 实机/HIL 验收

需要实机/HIL验证：

1. I2C2 初始化后 SCL/SDA 保持高，BUSY 清零，DA218E 能读到 CHIPID `0x13`。
2. EC800M 打印真实 `CEREG/CGREG` 状态，达到 `1/5` 后进入 PDP/READY。
3. 主、备 TCP 可独立连接并各自完成注册鉴权。
4. 平台抓包确认消息头手机号、`0x0100` 字段、流水号、转义和校验正确。
5. 两个平台分别返回不同鉴权码后，设备重启可在各自通道直接鉴权。
6. GNSS 首次有效定位后两个在线平台均收到真实 `0x0200`；单路断网时另一平台持续定位。
7. 断网、PDP deact、服务器拒绝、错应答和模组复位不会引发无限重试或整机重启风暴。
8. 连续运行期间无看门狗复位、明显主循环阻塞或 RAM/栈水位异常。

## 12. 非目标与剩余风险

- 不实现 JT/T 808-2019。
- 不整体移植 N32G452 的四千行 JT808 实现、低功耗事务、定位完整性、RTC 同步或转向加报功能。
- 不修改 FOTA HTTP 契约、外部 Flash 布局、Bootloader 契约或生产平台部署。
- 不确定 DA218E 最终量产地址；只修复 AF 根因并通过 CHIPID 实测确认。
- 主、备服务器是否接受相同 PID、制造商 ID、型号及车辆标识仍依赖平台建档，需要联调验证。
- 配置格式升级、双鉴权码和双会话属于高风险持久化/协议变更，必须通过掉电恢复、RAM guard 和实机双平台验证后才能作为发布输入。
