## 目标与实施门槛（实验前冻结）

- 目标：App 余量至少 4096 B；若基线不变，需净省 3032 B。目标不是必须通过修改实现的承诺。
- 局部低成本：单个职责、至多两个生产文件、无新 API/依赖/数据格式，净省至少 512 B。
- 中高成本：公共格式化器、跨模块/大状态机重构，净省至少 2048 B；替代实现、表、适配器的新增字节必须扣除。
- 达到字节门槛只是必要条件：日志与协议逐字节一致；保留截断/返回值、时序约束、失败恢复、安全控制和数值判定；静态 RAM、已知主调用链栈帧和受影响局部最大栈帧不得增加。
- 不增加间接调用、动态分配、字符串运行时解压、持久化状态或无界等待。不以缩减功能、诊断、校验、回滚、掉电恢复换容量。
- 实施前必须有相关真实 C 的等价/回归验收；实施后运行定向测试、构建、相关门禁与 diff --check。全程序栈证据不完整不能称为 RAM 安全；硬件路径需要实机/HIL 验证。

## 测量方法与停止规则

1. 以容量工具确认的 Flash 加载跨度/BIN 为主指标，不能使用 ELF/HEX 文件大小或简单累加重叠符号。净收益 = 同输入基线加载跨度 - 候选加载跨度。
2. ELF section / MAP / 符号用于定位，静态 RAM 使用 .data + .bss（另列 heap/stack reservation），栈使用最终 LTO .su 与 stack-report。完整保留失败命令和退出码。
3. 先审四方向：格式化共用、AT/F39、字符串去重、状态机公共步骤。无法给出安全局部变换或可信收益依据的高成本项，停止于审查，不先写完整替代库。
4. 本轮最多三个候选全量构建，每个仅一轮，无参数穷举；仅超过门槛的候选才进入生产实施验证。预算耗尽或所有候选低于门槛就停止，不因累计小收益接近目标而绕过单项门槛。
5. 格式化器先看可替代的实际链接体积和语义差异；字符串先看链接器已合并情况；AT/F39试验局部禁单次调用内联；纯字面量日志试验直写（输出不变）；大型掉电状态机若没有明确重复块收益则不重构。
6. 结束时重新核对输入哈希并记录每项“采用/拒绝/未证明”及成本，不把未测估计写成已节省空间。
