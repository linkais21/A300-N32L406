# 稳定性与 OTA 可靠性修复

依据：工作区 outputs/firmware-quality-audit-20260919/企业级代码质量与资源优化诊断.md。
报告 Q02/Q05/Q08/Q09 涉及栈、阻塞和 OTA 校验风险，并未证明内存泄漏或已经发生的栈溢出。

## 边界与验收

- 保留全部功能、协议、安全校验、Flash 布局和持久结构；不提交、烧录或部署。
- 保留已有未提交改动；本轮修改前文件备份在 outputs/stability-ota-repair-20260919/before。
- 每项先用生产 C 的 host harness 复现，再实施最小修复。
- 正常 tick/正常 OTA 路径保持原契约；故障路径必须有界、释放 owner，不启动损坏镜像。
- 新构建使用独立目录，不覆盖交付固件，不刷新版本头；执行 App/Boot 构建及相关门禁。

## 执行顺序

1. EC800M 阻塞等待：冻结 tick 注入 AT response、prompt、QIRD、残留清理和 alive probe；补充独立于 tick 的终止边界，确认 owner 释放及正常响应/超时回归。
2. OTA 续传：测试 If-Range 不匹配后返回完整 HTTP 200 + 新 ETag；必须先持久化零断点，随后擦除旧前缀，继续校验签名；206 错误 ETag 仍拒绝。覆盖断网、重启、部分扇区和日志掉电。
3. Boot 续装：注入已提交前缀损坏、读失败、最终页/BCR 切点；转入 TRIAL 前核对整个内部镜像与已验证候选一致，失败不跳转，保持现有回滚。
4. 运行定向/相关全部 host tests、App/Boot 全量构建、Flash/release/RAM gate，记录真实失败，禁止降低门禁。
5. 审查差异和验证输入哈希，逐项记录影响与剩余实机/HIL 验证。

## 实机验收（host 不替代）

长时间双路联网、GNSS+OTA 并发、最大 F39/SMS 栈水位、tick 故障恢复；下载扇区/BCR/安装页每阶段断电；断网重连、签名拒绝、试运行失败回滚。
报告中的型号/引脚冲突不在本轮修改范围。完整 RAM 上界若仍未证明，保持禁止发布结论。
