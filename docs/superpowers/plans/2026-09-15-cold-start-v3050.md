# V3.050 冷启动修复与烧录验证包

依据：RETRY 实机停在镜像选择返回后的恢复循环，BCR 栈残留为零，稍后只读 NOR 两槽均为 FF；详见 cold-start-investigation-20260915.md。

本地执行，保留已有工作树，不提交、不烧录，不操作仍供电的设备。测试包递增到 V3.050；输出 Combined HEX/BIN、同版本 OTA、ELF/MAP、哈希和冷启动记录表。OTA 仅含 App，不能安装本轮 Bootloader 修复；本轮必须用 Combined 测试。

1. 保存本轮起点，增加生产 C 回归：异常全零随后正常、瞬态/持久 I/O 错误、持久损坏、较新 Pending、防降级和正常启动；证明旧代码不能恢复。SPI 假外设验证忙等待、片选间隔及超时。
2. SPI 片选建立/保持/间隔明确化，传输结束等 BSY 清零且保持有界；BCR 读取增加芯片身份检查，不能把未响应的 FF 当作空白。
3. BCR 双槽读取最多 20 次，失败之间至少 100 ms 核心周期等待并喂狗，真实损坏仍 fail closed；不反复执行工厂擦除、记账或安装。增加有界 UART 启动/重试/拒绝日志。新接口仅 Bootloader 内部，不改持久格式。
4. 定向 RED/GREEN、全部 Bootloader/Flash/FOTA 相关 host 回归，独立目录构建 App/Bootloader，执行 release/RAM/stack 门禁及差异审查。
5. 按既有 HIL 交付方式封装新目录，保留未通过的全程序 RAM/栈门禁事实，release_approved=false。校验 HEX 装载字节、版本、地址、工厂请求、OTA 和哈希。说明首轮清配置、连续上电方法、串口日志标记和异常保留现场方法。

硬件验收：用户重复冷启动至少 50 次，包含不同断电间隔，观察正常启动及错误恢复；未实测前不声称已根治。设计中的等待是有界恢复窗口，不是对上电电路参数的证明。
