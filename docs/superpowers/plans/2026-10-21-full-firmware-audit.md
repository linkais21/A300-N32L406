# 刚编译固件的完整功能、质量与资源审核

## 边界和验收

基线为 build-track-repair-20261021 的当前工程验证固件及对应未提交源码。用户确认尚未烧录，不进行设备操作。源码缺陷修复、保持外部行为的优化已授权；保留原发布身份和历史产物，另建 build-full-audit-20261021 验证候选。没有真实设备或生产平台验证结论。

最终报告按实际业务场景组织，不包含单元测试内容。协议回放、主机模拟、静态证据和未实测项目明确区分；不得把主机回放说成执行了目标 ARM 镜像。

## 步骤

1. 保存基线源码、Git 状态、ELF/BIN/MAP 与证据身份；核对构建配置及版本一致性。
2. 审核全部参与构建的 App 与 Bootloader 模块、时间/长度边界、ISR、所有权、掉电事务、协议与业务路由；平台关联代码仅审核实际契约，不接触运行数据库或生产服务。
3. 测量 Flash/RAM 符号分布、全局缓冲、堆限制和栈证据，核对编译与链接优化、死代码消除、双精度与格式化等热点；CPU 占用和 IRQ 延迟只报告可证的静态结论，实测保留。
4. 执行注册鉴权、SMS/8300 参数、8103/8104/8105/8106/8107、日志及参数回报、盲区离线/重连、OTA/恢复、AGNSS、ACC/振动与轨迹/转角/漂移等协议及故障回放。补足跨模块和长期运行边界场景；内部回归不写入最终功能报告。
5. 对确认缺陷先记录失败再作最小修复；对体积/性能优化采用等价性证据和独立候选构建，不删除日志/校验/超时/恢复。重新运行受影响场景及资源门禁。
6. 完成差异检查、证据身份和功能报告；逐条列问题、风险、已修复项、资源前后值以及未实测场景。不提交、不推送、不发布、不烧录。
