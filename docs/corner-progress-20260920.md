# 本轮优化：连续缓弯补传恢复推进（2026-09-20）

本轮在现有 V3.066 未提交工作树上修复一个拐角补传阻塞路径，仅修改 `src/jt808.c`。已完成源码路径核对、修改前后独立构建和静态容量检查；尚未连接设备进行道路或长时间运行验收。没有生成正式升级交付包，没有烧录、部署、提交或推送。

## 实际功能问题与修复

车辆持续缓弯时，可能先积累三个待确认的拐角点，再达到转弯确认角度。原调度发现三个坐标缓存全部被占用后，会把后续有效的新航向标记为“不新鲜”，算法因此停止累计角度。候选点无法得到确认和发送，缓存也无法释放，后续转弯同样可能漏报。此问题影响拐角额外补点，不等于设备主循环死机或所有定位上报停止。

源码可推导的触发序列如下，属于路径分析，**不是实车采集或已执行的功能验证**：保持有效定位和约 65 km/h，每秒航向依次为 0°、3°、6°、9°、12°、15°、18°、21°。当前算法在此速度下候选点间隔为两秒。

| 航向 | 原路径 | 修复后路径 |
|---|---|---|
| 0° | 建立初始航向 | 相同 |
| 3°、9°、15° | 三个候选点逐步占满缓存，累计尚未达到20° | 相同 |
| 18° | 缓存已满，新航向被阻止进入算法 | 保留三个候选坐标，继续累计到18° |
| 21° | 仍被阻止，无法确认转弯 | 累计到21°，确认转弯，进入原有发送或盲区存储路径 |

修复将“保存新的候选坐标”和“继续判断转弯”分开：没有空位时不覆盖任何已有坐标，但仍向算法传入有效新航向；算法自身已有队列容量检查，不会新增第四个候选点。发送成功或盲区保存成功后，仍按原顺序释放候选点。同步删除只写未用的局部标志和重复时间戳赋值。

范围自审核对了：三个缓存各自被候选点引用时不被覆盖；满队列的追加直接返回；未确认转弯取消时清空候选点并允许后续重新取样；旧航向不重复累计；待完成的盲区写入仍保留原阻塞保护；进入转弯后继续使用原坐标查找、在线发送及离线存储流程。本轮不改变缓存大小、存储格式、上报频率或算法角度策略。

已有规格差异继续明确保留：配置结构的 `anglerep_angle` 默认值为30，而当前实际算法使用累计20°及同向确认，调度未读取该配置字段。此前 `corner-v3062-delivery-20260919.md` 已记录此差异；本轮沿用现行算法修复阻塞，不将配置字段描述为已生效，也不擅自修改阈值。
