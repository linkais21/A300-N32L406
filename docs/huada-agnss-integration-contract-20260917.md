# 华大 AGNSS 对接约束与实施顺序

## 范围与冻结边界

仅对接 TAU804M 使用的华大 AGNSS，不增加其他接收机实现。保留历史配置枚举兼容性。
设备稳定性、已有功能和升级可靠性优先。冻结 FOTA、Bootloader、升级校验/回滚实现及全局编译策略；此前约 1.6 KiB 内联实验不直接合入。
本文件记录资料核对结果和实施前置条件，不代表下载、注入或实机验收已经完成。

## 原始依据

- 工作区 `文档/华大AGNSS/T-5-2003-002-A-GNSS应用指南-V1.4.docx`：技术支持流程、方案流程、星历访问地址、数据帧格式。
- 同目录 `T-5-2204-ALLYSTAR GNSS 接收机二进制协议规范-V2.3.6.docx`：二进制帧、ACK/NAK、AID 信息。
- 同目录 `03_A-GNSS参考代码/src/agnss.c`：时间、位置、星历封包示例。示例用 3 ms 延时替代 ACK，不能作为设备端稳定性实现直接移植。
- 原件只读。段落提取文本位于本地 `build-huada-contract/`，不是发布输入。

## 已确认协议

1. 指南架构：客户服务器通过带账号的 FTP 拉取华大星历；终端通过 HTTP/FTP 从客户服务器获取数据。现已从历史 A300 源码找到设备端 HTTP 接口，详见下文；服务在线状态与新鲜度仍未验证。
2. 华大提供 GPS、北斗、GPS+北斗 HDB 文件。双模数据文件为 `HD_GPS_BD.hdb`，其中是已封装的 ALLYSTAR 二进制帧。
3. 帧头 F1 D9，组/子 ID，双字节小端负载长度，负载及双累加校验。逐帧校验通过后才能注入；网络数据不得直接作为任意 GNSS 控制指令转发。
4. 注入顺序：可选 AID-TIME、可选 AID-POS、必选星历。每帧等待匹配 ACK 后推进；NAK、错误校验、超时必须有界退出。ACK 为 05/01、NAK 为 05/00，负载标识被确认的命令。
5. 时间误差需在 ±3 秒内，位置误差需小于 75 km。不能因为日期非零或存在旧坐标就认定满足条件。
6. 指南要求注入前冷启动。这与“不能打断当前正常定位”的要求存在条件冲突：不得周期性无条件冷启动；仅在待定位的辅助获取流程中考虑，具体 TAU804M 固件行为需要实机/HIL 验证。

## 当前代码缺口与稳定性风险

- `agnss_manager.c` 目前仅驱动已有缓存读取和注入，没有完整下载流程，且未检查 `agps_en`。
- `agnss_huada.c` 当前连续发送完整帧，未等待模块 ACK；结束返回成功不能证明模块接受星历。
- `gps.c` 尚未形成可供 AGNSS 状态机使用的二进制 ACK 交接；新增解析必须兼容现有 NMEA 半包/粘包处理，并保持 ISR 轻量。
- 网络接收回调目前通向注入器。HTTP 头、错误页、任意控制帧必须在下载层拒绝，不能注入模块。
- `agnss_storage_begin()` 整槽擦除并持有 Flash owner 至提交/中止。不能直接将该调用串进新下载流程；应评估分步擦除、短时占用、下载失败释放和升级优先退出。
- 存储校验存在整文件扫描。需要量化每次主循环耗时，避免仅“喂狗不复位”而丢失串口数据或拖延既有任务。

## 后续实施顺序

1. 以历史 A300 华大下载接口为迁移依据（见下文），补充响应长度、数据生成时间及有效期、异常响应验证。不推断 FTP 账号就是设备 HTTP 凭据。
2. 保存当前构建输入与回归基线。先做局部 Flash 优化隔离实验；只在输出、栈及相关回归证据满足要求后保留，不修改升级实现，不删既有功能。
3. 先为华大帧校验、ACK 匹配、超时、取消/重入编写实际 C 的失败回归，再实现有界注入状态机。覆盖其他命令 ACK、迟到 ACK、NAK、重复帧、损坏及截断帧。
4. 根据已确认服务契约接入下载，单独使用 AGPS 通道；设置头/体长度上限、事务期限及有限重试。禁止从接收回调递归调用 modem 事务；尊重 AGPS 使能。
5. 缓存采用现有布局及 owner 机制，保留旧有效副本；未完整验证不得提交。升级开始、网络断开、休眠或失败时释放 AGNSS 占用并清理半包。
6. 检查 Flash、静态 RAM、最坏栈和每轮处理时间；运行相关 host 回归与完整发布门禁，不降低门槛。当前历史结果中的整体栈证明缺口不能视为通过。
7. 实机/HIL：冷/热启动定位、坏星历、ACK 丢失、断网、掉电切点、AGNSS 与升级/盲区存储争用、连续运行及功能回归。全部完成前不宣称稳定性验收或对接完成。

## 已找到的 A300 HTTP 对接

按用户提供的源码线索，已定位工作区只读历史仓库 `fota-platform/A300-N32G452/app/`：

- `src/agnss.c:18`：路径 `download/ephemeris/HD_BDS.hdb`。
- `src/agnss.c:187` 的 `hd_agnss_do_inject()`：默认主机 `39.108.211.33`、端口 80；允许配置 `agps_ip/agps_port` 覆盖。具体回退判定以旧源码为准，不直接照搬其首字符判断。
- `src/ec800m.c:1956` 的 `ec800m_http_download()`：在 `EC800M_CH_AGPS` 通道请求 `GET /<path> HTTP/1.1`，带 `Host` 和 `Connection: close`。该华大调用不带认证头或账号参数；不引入同文件其他模组的认证逻辑。
- `app/Makefile:43` 将 `src/agnss.c` 纳入构建，`src/main.c:838` 从主循环调用 `agnss_process()`，分支最终进入华大实现。这是源码调用链证据，不等于当前服务器可用性或实机成功证据。

默认完整 URL：`http://39.108.211.33/download/ephemeris/HD_BDS.hdb`。

该路径是旧工程实际采用的 BDS 文件名，与华大指南中的 `HD_BD.hdb` 命名不同；服务端可重命名文件，迁移先保留旧接口，不擅自改成指南名字或 GPS+BDS 路径。需验证响应确实包含目标模块支持的 F1 D9 星历帧。

指南推荐使用域名，历史项目使用固定 IP，存在运维策略差异。当前先保留配置覆盖能力，不擅自指定未知域名。尚未对远程服务发起访问，也未确认响应新鲜度、缓存策略和实际鉴权要求是否变化。

旧下载代码使用 8 KiB 静态缓冲，单次连接/下载存在秒级阻塞；长度不匹配只打印日志后仍返回数据，注入用 3 ms 延时代替 ACK。当前 N32L406 不复制这些实现：应使用有界分步下载、严格完整性检查及 ACK 状态机，并保持升级代码冻结。服务器是否需要新建不再作为固件协议设计的阻塞项。
