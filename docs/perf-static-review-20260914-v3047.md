## 后续路测与闭环要求

当前版本路测可用于收集移动功能基线，但普通串口日志再长也不能补齐缺失的性能计数。

1. 固件侧先补齐 PERF-01 重复拒绝样本的计算复用，增加真实 C 回归：重复调用、速度/配置变化、基准变化和逐点里程等价。不得直接把拒绝点写成新里程基准。
2. 准备低扰动性能统计：里程调用数/距离计算数/复用数及周期、主循环间隔分布与最大值、AGNSS 校验次数/payload 读取量/注入耗时。低频汇总，不能逐次串口打印。构建并检查 RAM/栈预算，保留当前 3904 B 实测告警。
3. 公司静态对照及固定输入回放用于量化性能；采用相同硬件、参数和输入的优化前后版本。PERF-02 必须实际触发同一测试包注入并核对输出。
4. 路测建议：出发前静止约 5 分钟，正常行驶约 20～30 分钟，包含低速、转弯、正常停车，停车后继续记录约 5 分钟。无需特意进行危险动作。
5. 串口从上电开始连续保存到结束，建议开启电脑接收时间戳。记录固件版本、出发/停车/结束时间、车辆仪表起止里程、供电与 ACC 状态、途中人为重启或参数修改。路测期间尽量保持配置不变，避免混入 OTA。
6. 路测比较移动计程与停车漂移、GPS 丢句、复位、内存告警；性能指标需结合对照数据，不能从不同路线直接计算加速比例。

满足代码回归、同输入性能对照、实机功能验证后再关闭对应 PERF 项。RAM 告警和静态误增里程应独立跟踪，不能由 PERF 测试通过自动关闭。
