# 日志平台设置指令核查

核查依据：工作区 `文档/1_定位终端指令说明V1.0.xlsx` 的 Sheet1；Sheet3 是历史审计记录，不作为当前固件验收依据。日期：2026-09-21。

## 平台下发方式

设备每次上电／重启，等待网络和 JT808 在线后查询一轮，轮内最多尝试三次。取消 60 秒轮询后，本轮结束才添加的配置要等下一次启动查询。

平台在 `0x92` 配置响应中使用一个类型为字符串（`0x03`）、名称为 `Pass`（区分大小写，10 字节补零）的配置项，值填完整指令，例如 `FREQ,30,180#`。不要填写表格里的“短信指令：”前缀。多参数使用一条 `DUALSET,...#`；字符串长度字段为一字节，最多 255 字节。

设备复用 F39 解析、校验和执行路径；参数持久化成功后发送 `0x14`，再执行网络重连等后续动作。回包发送成功只表示模组接受，不证明服务器已收到。

## 已覆盖的设置／动作

`tools/tests/test_cfg_query_f39.py` 使用生产 cfg_query、at_config、F39 代码，模拟 UDP 响应和持久化接口，验证以下项目：

| 指令 | 验证内容 |
| --- | --- |
| DUALSET | 组合修改；非法后项不允许部分保存 |
| PID | 11 位数字 ID 保存，非法值拒绝 |
| IP / FIP / FIP,0 | 主副地址和端口修改、关闭副平台 |
| FREQ / HBT | 定位、心跳间隔保存及定时刷新 |
| MODEL / SPEED | 终端型号、超速阈值保存 |
| APN | 自定义及空账号密码、AUTO、0；确认先于 PDP 重启；重复投递 |
| GPSDUP | 休眠定位上报开关 |
| MLG | 500 对应 50000 米，3003 对应 300300 米 |
| CAR | 数字省份编码转车牌，例如 18 转粤 |
| GPSBDS | 1、2、3 三种模式，当前测试接收机为 TAU804M |
| GMTSET | 东八区、西五区参数 |
| VIBSENS | 灵敏度保存、越界拒绝 |
| RELAY | 低速有效定位允许断油电，速度不低于 20 km/h 拒绝，恢复油电 |
| RESET | 确认后按当前延时执行重启 |

上述验证不代表任意类型的原生配置字段或任意组合均受支持；统一使用单个 `Pass` 文本项。RELAY、RESET 是动作，不是持久参数，不能按普通组合参数使用。安全校验始终保留。

## 差异与验证边界

- Sheet1 PID 备注称未严格校验，当前实现实际要求 11 位数字。
- RESET 文档写约 200 ms，当前 `F39_RESET_DELAY_MS` 为 100 ms；此次保留现状。
- Sheet1 包含 PARAM、IP 等查询指令。此 UDP 配置通道只回传协议确认，不回传 F39 文本查询结果，不能据此保证平台展示查询值。
- 主机测试验证配置候选值、模拟保存、执行回调及确认顺序；真实 Flash 保存、GNSS 切换、传感器灵敏度、继电器和平台收发需要实机/HIL 验证。
- 本轮未修改固件逻辑。上轮完整构建被已有 `src/jt808.c` 中未声明的 `rc` 阻断，不能声称当前固件完整构建通过。
