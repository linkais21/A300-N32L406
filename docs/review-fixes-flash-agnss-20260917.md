# Review 修复与 Flash / AGNSS 容量审核

本轮在已有未提交工作树上修复两项缺陷，并进行隔离容量实验。未提交、推送、烧录或覆盖既有交付包。优化候选没有安装为默认构建，AGNSS 下载服务没有在本轮对接。

两项修复已进入标准源码：

1. 工作模式报告增加 RAM-only `report_id`。新动作分配非零编号，重试保留编号，告警合并更新编号。`jt808_send_location_work_mode()` 增加第三个参数；待落盘记录完成仅能确认同一动作，其他动作继续生成自己的报告。编号不进入 JT808 报文或 NOR 记录，不改变持久化布局。队列按 ARM 字段布局排列，删除可由动作类型推导的 `mode_entry`，控制状态增量。
2. ADC 两个通道独立更新。车辆通道成功即可判断断电边沿并请求里程保存；电池通道失败不再屏蔽该动作。电池通道成功才判断低电告警。`adc_monitor_valid()` 仍要求两路都成功且新鲜，供产测使用。

RED：修改实现前，真实 `jt808.c` 夹具在旧超速报告待写期间提交紧急告警，失败于新记录 event_id 未变化；真实 `adc_monitor.c` 夹具在车辆零伏、电池转换超时时失败于断电告警/里程保存未发生。GREEN：修复后上述断言通过；补充了相同告警的新动作、合并告警、ACC 改变、重试 ID 保持、独立电池成功和失败样本不重复报警。

最终 24 项定向脚本通过，命令、退出码和日志见 `../build-review-fixes-20260917/validation/commands.json`。保留了初次旧接口源码契约检查失败记录，后续已同步三参数接口并通过。覆盖工作模式队列/ACC/振动/休眠、JT808 双会话/首包/定位过滤/参数、ADC/里程、盲区存储/补传/拐点、AGNSS 调度/缓存/流/共享内存、发布身份和必要栈帧。

ARM GCC 14.3.1 修复版：App 105992 / 106496 B，剩余 504 B；静态 SRAM 18024 B，已知最大调用帧和 2400 B，堆/IRQ/未知项前余量 4152 B。与本轮前记录相比，Flash 增加 144 B，静态 SRAM 减少 56 B。编译/链接、Flash guard、release-guard、信任锚和必要帧预算通过。

完整 `release-gate` **失败（真实 make.exe exit 2）**：79 个缺失帧、54 个间接转移、181 个尾转移及 1 个调用环，缺少完整栈/堆/异常边界。4152 B 高于必要阈值 4096 B，仅为必要条件，不能解释为已证明 RAM 安全。证据：`../build-review-fixes-20260917/review-gate.log`。

Flash 仍有优化空间，但当前余量不能承诺容纳完整 AGNSS。隔离实验全部保留签名、回滚、校验和业务功能，没有修改链接分区边界：

| 构建策略 | App / B | Flash 剩余 / B | 堆/IRQ/未知项前 RAM 余量 / B | 结论 |
|---|---:|---:|---:|---|
| 默认修复版 | 105992 | 504 | 4152 | 必要预算通过，完整栈证据不足 |
| 直接放开单次调用内联 | 104256 | 2240 | 4080 | 省 1736 B，但 RAM 必要预算失败 |
| 仅 FOTA 状态机限制内联 | 104444 | 2052 | 4056 | RAM 必要预算失败 |
| 仅 AGNSS 调度设 noinline | 104312 | 2184 | 4076 | RAM 必要预算失败 |
| `main` 与 FOTA 状态机局部限制内联 | 104380 | 2116 | 4128 | 省 1612 B，必要预算满足；完整栈证据仍不足 |

最后一项使用默认 `-Os -finline-limit=64`，仅在两个函数增加 `optimize("no-inline-functions-called-once")`；源码覆盖、完整参数和结果位于 `../build-review-local-inline-20260917/`。它是优化候选，不是发布包，也没有替换默认源码。其静态 SRAM 18008 B、已知帧和 2440 B；编译器行为依赖版本，未来修改需重测。另在队列最终布局调整之前测试 `-Oz`，与当时 `-Os` 均为 105992 B，无收益；不能把该早期产物与最终产物视为同一输入。

各候选摘要：`../build-review-fixes-20260917/flash-experiments.json`。所有构建均以 `flash-guard` / `stack-report` / `release-gate` 等目标启动，没有调用会刷新版本的 `all`，版本和计数器不变。

AGNSS 审核结果：

| 部分 | 当前证据 | 对接影响 |
|---|---|---|
| 华大流解析、时间/位置/辅助帧注入 | `src/agnss_huada.c`，现有 host 流测试通过 | 属于基础能力，不能等同于在线 AGNSS 可用 |
| 缓存元数据、CRC/SHA、双槽和读快照 | `src/agnss_storage.c` | 读链已接；生产源码未调用 begin/write/commit |
| 联网数据获取 | `src/main.c` 注册 RX 回调，但无 AGNSS 通道的生产打开/请求状态机 | 服务地址、鉴权、响应格式、下载/超时/重试/提交链尚缺 |
| 缓存时效与启停 | 调度器读取缓存；无缓存时 60 秒后重试。未使用 `agps_en`；metadata timestamp 未用于失效判断 | 接入时必须明确服务时效、UTC 可信来源和开关语义，不能无限复用旧辅助数据 |
| 运行资源 | `s_workspace` 已占 4096 B SRAM；共享 service workspace 1024 B | 不能再增加同等级整包缓冲，也不能直接把两块缓冲重叠，部分帧与下一读块生命周期重叠 |
| 校验延迟 | `verify_payload()` 在一个调用中遍历缓存；get_latest 可校验两个槽 | 对接大包时需测主循环延迟，考虑分步校验并保留数据身份与完整校验 |

重要容量实验：通过 `--undefined` 仅保留现有 `agnss_storage_begin/write/commit`，没有添加联网下载代码，默认修复版已增至 **106580 B**，链接器报告超出 App **84 B**（增加 588 B）。证据：`../build-review-agnss-writers-20260917/build.log`。该构建失败，没有可交付镜像。真实调用后的优化结果可能不同；588 B 不是完整 AGNSS 的新增预算。

外部 NOR 已给 AGNSS 分配 316 KiB 区域（其中双数据槽各 152 KiB，另有元数据和尾部保留）。这是辅助数据空间，不能抵消 MCU 内部 App 指令空间的不足。

建议按下列顺序继续优化；除首项外，下表是源码/链接证据支持的方向，尚未测得最终节省量，不能相加承诺：

| 顺序 | 方向 | 证据与约束 |
|---|---|---|
| 1 | 局部内联边界替代全局禁止 | 已测得 1612 B；先补足栈证据并对候选执行 ARM/HIL 压力验证 |
| 2 | 合并调试串口与内存报文格式化的重复实现 | 同时链接自研 dbg_printf 和 newlib snprintf/vsnprintf 及格式化/堆支持。仅 `_svfprintf_r`、`_printf_i`、`_printf_common`、`__ssputs_r` 的不重复函数体已约 1494 B；这不是可直接删除的净收益。需严格保留截断返回值、宽度、符号、格式和所有协议报文测试 |
| 3 | 合并旧控制台与 F39 的重复命令实现 | `handle_cmd` 约 1080 B 函数体，尚不含字符串和专用辅助函数。必须逐命令证明等价，保留原有设置、权限、安全判断和失败行为，不能整段删除 |
| 4 | 精简重复诊断字符串和重复数字格式化 | 当前 `.rodata` 13248 B，LTO 合并后的字符串区约 11057 B，包含协议和诊断，不能全部裁剪。优先共享重复文本/转换逻辑，不删失败恢复日志或原始验收所需字段 |
| 5 | AGNSS 坐标量化收窄为有界 int32 | 当前唯一 llround 调用在华大位置注入，函数体约 206 B，另牵连转换辅助。可研究保留正负半值舍入的有界转换；必须先明确无效坐标、负海拔、消息单位和供应商协议，不能直接强转 |

不建议删除当前缓存源码作为“节省”：未被调用的写入接口本来就已被 LTO/GC 裁掉。也不建议削减签名、回滚、NOR 掉电事务，或未经布局兼容验证压缩 Bootloader 分区。

额外工具问题：仓库本地 `mingw32-make.CMD` 在括号块中使用 `%errorlevel%`，观察到内部 gate 失败而包装脚本返回 0。本轮未修改该工具，后续记录直接调用 WinLibs 的 `mingw32-make.exe`，以 exit 2 和门禁日志为准。
