# 里程数学 + 日志可测量瘦身试验

结论：范围受限的双精度数学候选，加上保守日志裁剪，将 App BIN 从 104560 降到 **97636 字节**，净减少 **6924 字节（6.62%）**，当前 App 分区剩余 **8860 字节**。这证明数学实现存在 KiB 级优化空间；并不证明已经满足新增 AGNSS、产线和 0x8103 后的容量要求。

本轮是隔离源码试验。**生产 `src/`、`include/`、主 Makefile、版本与已有交付包均未修改。** 候选不能声称逐位/逐决策等价，没有替换默认固件、递增版本、生成新版烧录包、烧录或部署。当前默认固件余量仍为 1936 字节。

## 数学试验及兼容性

两个候选都只替换 `mileage.c` 的内部 `haversine_m()`；保留坐标 double 存储、里程更新状态机、0.5/1000 米判断、原始防漂参数 `/10`、整数累加、持久化、失败退避、复位代次和日志调用。

1. **float 候选**：double 经纬度相减后，使用标准库 `sinf/atan2f/sqrtf`，跨日期线先归一化经度差，极区使用余纬的正弦计算纬度余弦。收益有限，边界差异较多，不推荐作为后续主方向。
2. **受限 double 候选**：有效经纬度范围内，19 阶正弦多项式仅用于 `[-π/2,π/2]`；`sqrtf` 给初值，再做两步 double Newton 修正；小角度 asin 展开到五次项。距离足够大时返回 8192 米，因为现有累加上限是 1000 米，最大 `uint16_t stopdrift_thr /10` 为 6553.5 米，这些更大距离的精确值不参与有效累加或防漂决策。它不是通用地理距离库，不能复用于导航/围栏；如阈值类型、范围、日志或调用者改变，需要重新审查截断契约。

正弦多项式在精确算术下的首个省略项上界为 `2.572e-16`；这不是浮点运行总误差证明。小角度展开的省略项受 8192 米截断约束。实际舍入仍通过回放测量，ARM newlib/FPU 与 host libm 的差异尚需验证。

**回放真实 C，而非 Python 复制里程状态机：** 两个候选各 25128 组点对，其中 17682 组基线距离 <=1000 米；另有六条共 12000 点连续合成轨迹。覆盖随机局部/全球位移、两极、跨日期线、重复点、invalid fix、速度/防漂配置变化、0.5/1000 米边界、整米取整和防漂阈值。没有真实定位数据。

| 指标 | float 候选 | 受限 double 候选 |
|---|---:|---:|
| <=1000 米样本最大距离差 | 0.00012418 m | 7.647e-9 m |
| <=6553.5 米样本最大距离差 | 0.00116238 m | 7.749e-9 m |
| 状态/累加决策不同的点对 | 405 | 51 |
| 其中整米增量不同 | 281 | 37 |
| 其中累加分支不同 | 188 | 26 |
| 其中接受基准推进不同 | 229 | 28 |
| 连续轨迹逐点累计/基准差异 | 0 / 12000 | 0 / 12000 |

差异子项会重叠，不能相加。点对差异全部落在专门构造的边界组，普通局部/全球/极端样本组本次未发现决策差异。连续轨迹的六段结尾里程分别为 69132、71395、69989、70647、69688、70381 米，两候选与基线一致；不能据此推断任何实车轨迹都一致。

**不能因纳米级距离差就忽略业务差异。** 一个防漂阈值恰好为 999 米的合成样本，基线距离 `998.9999999999246` 被过滤，候选 `999.0000000001107` 则累加 999 米并推进基准。边界严格比较会放大极小数值差异；51 个差异样本不能全部算作“无影响”。具体输入和状态在 `decision-differences.json`，未通过放宽断言掩盖。

因此两候选均记录 `behavior_equivalent=false`、`release_approved=false`。后续正式采用前，应明确阈值附近的量化/容差语义，再证明累计偏差范围；本轮未擅自更改业务阈值或取整规则。

## 日志试验

最终仅裁剪四个白名单正常路径调用：

- `src/jt808.c`：每次 0200 的 acc/alarm/hist 跟踪。
- `src/jt808.c`：每帧接收 msg/sn/body 跟踪。
- `src/jt808.c`：每次接收 bytes 跟踪。
- `src/mileage.c`：每次里程增加的明细。

生成候选把这些调用指向一个静态空函数，保留参数求值副作用；编译/LTO 消除无用字符串和调用。没有对 `dbg_printf` 全局禁用，也没有修改中断、owner、计时、发送或重试路径。

保留全部 EC800M 日志、启动/身份/产线判定、周期健康与 GPS 统计、联网/认证/ACK 异常、OTA 状态与失败、配置命令应答、继电器及里程持久化失败日志。四条明细被裁剪仍是可观察行为变化，后续 HIL 日志工具若依赖它们，需要同步确认。

第一轮曾裁剪八条，包含四条 EC800M 收发诊断；`test_ec800m_qisend.py`、`test_ec800m_urc_demux.py` 明确拒绝该行为。已恢复这四条并重建最终候选，原始失败保存在 `build/mileage-log-host-regression-20260916`，未修改测试要求。
