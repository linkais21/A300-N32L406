## 已确认的问题

### 1. RAM 余量告警始终置位，优先级 P1

第 84 行首次 HEALTH 至第 3522 行末次 HEALTH，共 150 条，均为：

```text
HEAP_USED=0 STK_PEAK=2592 RAM_GAP=4088 RAM_AVAIL=6680 F=1
```

`src/main.c:162` 定义门限 4096 B；`:237` 附近在测量失败或 free_gap 小于门限时将 s_stack_margin_fault 置 1，随后 F 打印该标志。因此 F 不是 Flash 正常标志，是锁存的栈余量告警。本次每个采样本身都低于门限 8 B，不能用“只差 8 B”取消告警。

未见实际栈溢出或崩溃，也未见本窗口堆增长；这不能排除未覆盖路径的风险。V3.043 归档 stack-analysis.json 仍为 incomplete，已知主循环调用帧累计 2984 B。按本包可用 6680 B 计算，静态估算剩余 3696 B，尚未计全堆、IRQ 与未知调用；它和本次实测 4088 B 是不同口径，不矛盾。OTA 下载/验签没有被本日志覆盖。

下一步应优先承接原审计 RAM-01 的完整调用链/运行时验收，不得降低 4096 B 门限换取通过。

第 34–43 行建立检查连接、发送成功，随后 `HTTP response status=401 op=0`。本窗口只有一次检查，未进入更新下载或验签。JT808 正常不代表 FOTA 正常。

当前 App `src/fota.c:238` 的 send_request 只构造 GET、Host、可选 Range/If-Range 和 Connection，没有 X-Device-Key。当前默认配置 device_api_key 为空，且本次启动使用默认配置，但不能只把根因归结为“未配置 Key”：

- 用户提供的工作区指南要求设备 API 使用 X-Device-Key。
- 本地后端 `DeviceUpdateController.java:35` 附近说明检查无需共享 Key，下载/进度使用任务 token；`:67` 的检查方法无 Key 参数。

这是明确的契约/部署一致性问题。线上实际版本、反向代理及返回 401 的具体层尚未核实，不能断言是设备 Key、JWT 或旧服务器中的哪一种原因，也不能直接删除鉴权或擅自部署。本轮未访问线上或读取密钥。
