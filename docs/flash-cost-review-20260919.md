# Flash 优化收益/成本审核（2026-09-19）

结论：**停止本轮优化，不实施生产代码修改。** 三个预定实验均增大 Flash；高成本方向未证明能达到门槛。保留当前功能、日志、协议、数值策略和恢复机制，不为了达到容量目标继续扩大重构。

本结论只覆盖下述有界候选，不代表已证明整个程序没有优化空间。

## 2. 成本门槛与测量口径

- 局部低成本方案：单个职责、至多两个生产文件、无新 API/依赖/格式，净省至少 **512 B**。
- 公共格式化器、跨模块或大型状态机方案：净省至少 **2048 B**，扣除新实现、表和适配成本后计算。
- 两类均要求外部输出与行为不变、静态 RAM/已知栈预算不增，不新增动态分配、间接调用、运行时字符串解压、持久化状态或无界等待。达到字节门槛仍需等价回归和相应门禁，不能只看体积。
- 净收益 = 同一源码/工具链/版本下基线的 Flash 加载跨度 − 候选跨度。不能使用 ELF/HEX 文件大小、源码行数或重叠符号之和代替。
- 最多三个候选全量构建，各一轮；未达到门槛立即拒绝，不做参数穷举、不积攒多个低收益改动绕过门槛。三项预算已用完。

## 3. 实测候选与取舍

所有候选只存在于独立构建目录/overlay，没有写入生产源文件或主 Makefile。

|---|---:|---:|---:|---:|---|
| 基线 | 105432 | 0 | 17720 | 2536 | 保留 |
| 仅 at_config.c 禁止单次调用内联 | 105500 | **-68** | 17724 | 2544 | 拒绝：变大，RAM/栈也增加 |
| 仅 f39_reply.c 禁止单次调用内联 | 105464 | **-32** | 17720 | 2536 | 拒绝：变大 |

前两项测试“限制内联以保留公共步骤”的最小局部方案，不是对 AT/F39 全部可能重构的否定。字面量方案仅替换独立语句、单一字符串字面量、无 `%`、返回值被忽略的调用；排除 main/FOTA/签名单元，避免改变其既有编译边界。替换清单保存为 `literal-changes.json`。

负收益候选在容量筛选即淘汰，没有运行完整功能/HIL 验收，不能称其已验证行为等价；也没有进入生产实施阶段。

## 4. 四个审核方向

### 格式化代码共用：未证明满足 2 KiB 门槛，停止

ELF 中识别出的自定义日志格式化函数共 748 B（dbg_printf 648 B、print_uint_width 100 B）；识别出的 libc 格式化入口及核心共 1722 B。两者不是可直接相加的净收益，依赖、调用者、适配器及内联代码需要另算；这些数字也不是整个依赖闭包的严格上界。

`src/debug_uart.c` 有浮点、符号、宽度、零填充及小写 `%X` 等既有语义，直接替换成标准 printf 会改变行为；当前 nano 格式化的链接配置也不能直接承担原有浮点日志。反向以自定义实现替代 snprintf/vsnprintf，需要增加缓冲区容量、NUL、截断返回长度、`%.*s`、长度修饰和错误路径兼容，影响 HTTP/AT/F39/平台日志。

因此不新写私有 printf 库。潜在 libc 分配器依赖能否随之消失没有做闭包实测，不把它算成已证实的收益。维护兼容实现与跨模块回归的成本已属高档，当前没有净省 2048 B 的证据。

### AT/F39 命令：低成本实验失败，停止扩大表驱动重构

`at_config_process` 链接符号为 2504 B，但包含 LTO 内联后的业务，不等于可删除重复量。现有 F39 已有紧凑根命令表、共享标量/文本应答、合并的数值参数解析分支。SERVER/BSERVER 等仍可看到局部相似代码，但不能把整函数占用当收益。

两个独立内联实验分别增加 68/32 B。未找到足以证明局部净省 512 B 的删除项。扩大到统一控制台/F39 分发表会牵涉命令优先级、单位、持久化和副作用，还可能新增函数指针；本轮不实施，也不宣称这种重构必然没有收益。

### 字符串：完整重复已合并，不新增运行时压缩

LTO 字符串区 `.rodata.str1.1` 为 10878 B，按 NUL 分隔得到 437 个不同的非空片段，重复完整片段为 **0**。此检查只针对该区内完整片段，不证明所有常量/子串都无重复；MAP 同时显示链接器已有字符串合并/relaxation。

纯字面量直写实验没有减少 .rodata，反而增加 16 B 代码。前缀/子串拆分需要额外输出步骤和调用参数，不能将字符数直接计为净收益；字典解压违反本轮复杂度门槛。保留日志内容与现有存储方式。

### 大型状态机：大体积不等于冗余，不作高成本改造

`blind_zone_recovery_process.part.0` 为 4084 B、`fota_process` 为 1816 B。盲区看似相近的分支涉及 PREPARED/ACTIVE/CONSUMED、扇区边界、掉电修复和提交顺序；本轮没有识别出既能净省 2048 B、又不改变这些契约的明确公共块。

因此不改恢复状态机，不删安全/重试/恢复路径。若未来出现功能变更本身需要重构或有实测重复块证据，可重新审核，不能以“函数很大”作为实施依据。

## 5. 实际验证与限制

- 基线及三个候选全量 ARM 构建成功，无编译器 warning，容量检查通过但均有 LOW_HEADROOM；CONFIGURATION_CHANGED 是相对工具的历史参考，不代表本轮基线/候选失去可比性。逐文件候选参数另见 overlay 和实际编译命令，不能只看顶层 profile。
- 四组 stack-report 都生成了报告，其 report-only 退出 0 **不等于栈门禁通过**。
- 基线 release-guard、libc parser guard 通过。
- **完整 release-gate 退出 2**：首个失败为 ram-guard，因全程序栈证据不完整。当前报告有 68 个缺失帧、67 个间接转移、134 个尾转移、2 个内部调用、1 个环，不能声称发布门禁通过或 RAM 安全。
- 输入哈希复核无变化。只新增本计划、本文及独立分析/实验产物；保留用户已有未提交修改。没有提交、推送、烧录或覆盖旧交付包。
- 未新增生产行为，所以未进行候选功能回归或硬件验证。后续任何正式采用的硬件路径优化仍需要实机/HIL 验证。

## 6. 证据与复现

证据目录：`build/flash-cost-review-20260919/`。

- `audit.py`：三组有界实验；执行 `python build/flash-cost-review-20260919/audit.py`。已有 case 目录会拒绝覆盖，复跑需先复制脚本到同一 build 层级的新目录。
- `input-hashes.json` / `input-verification.json`：输入身份及结束复核。
- `commands.json` / `results.json`：完整命令、退出码、耗时、尺寸、RAM 与已知栈帧。
- `baseline/`、`at_noinline_once/`、`reply_noinline_once/`、`literal_direct/`：ELF/MAP/BIN、编译与栈报告；均为分析产物，非发布包。
- `inspect_elf.py` / `elf-review.json`：直接读取 ELF32 的符号/字符串统计，不输出字符串内容。运行 `python build/flash-cost-review-20260919/inspect_elf.py`。
- `baseline/release-gate.log`：保留真实失败；不能以后续成功命令覆盖此结论。

本轮最终净节省 **0 B**；当前余量仍 **1064 B**。取舍是接受当前已知容量限制，停止未经收益证明的复杂化。重新开启本方向需要新的可测量候选，或用户明确改变功能/兼容性/成本门槛；仅剩余空间紧张不足以自动放宽门槛。
