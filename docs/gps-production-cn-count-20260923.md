# GPS 产测逐星载噪比判据修正

用户确认：`N-C-H-S` 表示有效定位、至少 N 颗卫星各自 C/N₀≥C、0<HDOP≤H，连续 S 个不同完整 GSV 样本合格。`5-38-3.0-2` 的 HDOP 上限就是 3.0；上限 3.5 必须填写 `5-38-3.5-2`。无需全部卫星平均 CN≥38，也无需最大 CN≥43。

## 接口

- 新增本地调试查询 `GNSSSTAT,C#`，C 只能是两位十进制整数 20..50；格式错误返回 `GNSSSTAT=Fail!INVALID_ARGUMENT`。
- 查询选择 RAM 中的统计门限，不写 Flash、不修改 GNSS 模组设置。门限改变时清空旧 GSV 周期；同门限重复查询不清空，等待新的完整周期后统计才有效。
- 回包保留原字段，增加 `CNTH=C,CNGOOD=数量`。工具 V1.6.1 要求 CNTH 与订单第二段相等、CNGOOD≥第一段。CNAVG/CNMAX 只供观察。
- `GNSSSTAT#` 仍可查询，返回当前 RAM 门限统计。上电默认 CNTH=38，工具始终显式指定订单门限。
- 统计沿用已支持的 GP、BD/GB、GN 完整周期与 5 秒有效期；仅所选首信号带计数，避免同卫星多个频段重复；已有独立星座数据时不再叠加 GN 混合摘要。
- HDOP 输出三位小数，向上量化，避免 3.01 等超过门限的值被旧一位小数输出舍入为 3.0。
- 工具遇到旧固件缺少 CNTH/CNGOOD，明确提示配套升级，不退回旧平均值判据。原工具仍可查询原字段，但其旧判据不符合本次要求，须配套升级。

## 验证与交付边界

回归覆盖平均值低但 5 颗达标、仅 4 颗、等于门限、HDOP 3.0/3.5 边界、重复样本、失败后重新连续计数、错误/缺少门限字段、门限切换、部分周期、过期、计时回绕、频段去重及非法命令。

固件候选独立输出到 `build-gps-cn-20260923/`；保留现有 V3.073 版本字符串，以此目录和 SHA256 区分未发布测试候选，不作为可发布 OTA 新版本。未覆盖已有固件交付包，未烧录。

原现场有两个独立现象：第一台设备没有 GSV 数据；用户更换后，第二台设备有 GSV，且两台 App 可执行区一致。用户要求继续用第二台。此次修正的是已确认的产测语义错误，不宣称解决第一台 GSV 缺失的物理/配置原因。修改后仍必须有真实 GSV 数据才能通过。

完整 RAM/栈门禁未通过（全程序栈/堆/异常上界证据不完整）；AT 配置回归的 `strstr(console,"OK")` 断言在修改前头文件的隔离基线上同样失败。不得称全部检查通过或量产发布就绪。需要实机/HIL 验证配套固件+工具、上电和 ACC 唤醒后查询，以及缺 GSV/信号不足时正确拒绝。
