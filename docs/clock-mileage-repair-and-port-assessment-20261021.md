## 2. 本轮已经落地的修改

### 2.1 日期与定位数据一致性

- GGA 必须有有效 RMC 日历，RMC 接收年龄不超过 3 秒，GGA 与原始 RMC 秒时间差不超过 2 秒。
- 比较始终使用原始 RMC 时间，连续 GGA 无法自行延长 RMC 有效期；跨午夜等待新的 RMC 提供新日期。
- 不满足条件时拒绝认证新坐标，保留历史可信位置供未定位报文使用。
- RMC、保留位置及 NTP 的日期校验覆盖月长与闰年，拒绝 11 月 31 日等非法日期。
- 共享月长计算以减少受影响模块中的代码重复。

### 2.2 RTC 与 NTP

- 启动时用 TIM9 CH3 内部 LSI 捕获测量频率，参考厂商 SDK 的 IWDG_Reset 示例；没有新增引脚重映射、中断或 NVIC 优先级。
- 采集 65 次计数、平均 64 个八分频周期；计数回绕可计算，超范围或过捕获判失败。
- 测量同时受 50 ms 和 200,000 次轮询限制；失败沿用原有 /128/331 分频并输出 `ok=0`，不会无限等待。
- 成功后按实测频率配置 /32 的 RTC 预分频。该方案只校正启动时频差，不保证温漂被消除。
- NTP 保持 6 小时周期、失败 5 分钟重试，改用包含 STOP1 睡眠时间的单调时钟；模组不可用时等待恢复后尝试。
- 单调时钟按增量累计并保留不足一秒的部分，覆盖 SysTick 约 49.7 天回绕；依赖主循环持续调用，不能跨越整轮计数周期都不调用。

### 2.3 里程与补报

- 普通盲区记录由原有 34 字节扩展为 40 字节，在现有记录容量内加入 `0x01 / 长度4 / DWORD`，单位 0.1 km，保留卫星数与 CSQ。
- 旧 34 字节记录继续按原样读取和补报，不使用当前里程伪造历史里程；外部 Flash 布局、记录格式版本及事务阶段不变。
- 工作模式缓存原来的 34 字节已是“基础28字节+里程6字节”，保留该完整边界，避免截断后续 TLV。
- 转角候选点保存采样时里程，发送或入盲区时使用该值。复用冗余时间戳数组的位置，未为此增加数组 RAM。
- 入库失败后的重试及补报继续使用原事件内容，防止等待期间借用新里程。

没有增加“里程一律取历史最大值”的掩盖逻辑，没有清空设备里程或修改既有里程持久化算法。

## 4. 震动、弱信号静态漂移优化包 V1.330

**结论：可以移植其判定思想，当前不能直接复制完整模块或烧录其 G452 镜像。当前固件未加入这套算法。**

核对了移植包补丁与对应 G452 源码；`gps_report_filter_standard.c` SHA-256 为 `2438973ce613456bf2ff30f6f65d2dde8b7027ee83181b9f8f34c54e400ff364`，与包内身份相符。包内 ELF 的融合状态 `report.lto_priv.0` 为 **2,504 B**，当前 L406 `s_report` 为 **104 B**。仅替换该状态就约增加 2,400 B，尚未计入其依赖模块。包内交付证据标注整包 Flash 195,100 B、RAM预算 67,316 B，也不适合当前 104 KiB App / 24 KiB SRAM。

可复用的行为：

1. 振动仅作为运动候选，不因单次振动直接解除静止锁定。
2. 用分桶活动证据和轨迹连续性共同确认启动，避免静止振动、弱信号摆点累积里程。
3. 传感器失效或卡死时，保留 GNSS 独立确认运动的恢复路径，避免设备永久锁定。
4. 严格区分“允许上报新坐标”和“允许累计里程”，弱信号下的上报恢复不能直接放行里程。

需要适配：

- G452 使用 SPI 加速度接口，当前为 I2C；30/60 mg 等默认阈值不能替代当前 120/180 mg 策略直接上线。
- 依赖 `gps_motion`、定位完整性分级、独立速度新鲜度和 CN0；当前接口不齐，不能删掉这些条件后声称等价移植。
- 原实现有四套各 17 点历史轨迹。适合 L406 的方案需共用有界历史、压缩坐标/时间或改用经验证的累计统计，并用同一回放验证结果差异；不能只裁掉点数而保留原验收结论。
- 弱信号独立逃逸需较长确认窗口，例如约 120 秒/40 米；改善误报与启动延迟之间存在取舍，需要实测，不适宜只按强信号启动体验调参。

建议先完成当前修复的实机验证，再在明确腾出 Flash/RAM 后移植“振动候选+独立 GNSS 恢复+上报/里程权限分离”的最小闭环。资源目标和启动延迟验收需在实现前冻结。

## 5. D0/D1 异常诊断包

**结论：协议、离线解码和部分纯逻辑可复用；需要针对 L406 重做接入，当前未集成。**

该包名称含 A700，README 明确它是以 A300 标准 V1.323 为基准的源码参考，不是可直接烧录固件。

- D0 schema1 共 12 字段，描述启动原因、当前内存和链路事件；D1 schema1 共 18 字段，描述保留的故障上下文、寄存器和故障前内存证据。
- 用 ARM -Os 对参考核心做独立对象编译：`fault_diag` 代码及只读数据约 **1,074 B**，`.noinit` **176 B**、普通状态 **23 B**（最终对齐另计）；均超过当前余量。对象估算不等于最终链接增量。
- 配套 formatter 另约 1,329 B、CRC约 66 B 代码/常量，当前已有格式器与 CRC，应核对格式、截断返回值和 CRC 语义后复用，避免重复引入。
- 原包主机测试和解码测试通过，只能证明参考逻辑在模拟输入下的行为，不能证明 L406 的异常栈、保留 SRAM 或 Bootloader 行为。

具体接入要求：

| 边界 | L406 适配要求 |
|---|---|
| 故障采集 | 复用当前 HardFault 入口和 reset_diag，不新增第二套异常处理函数；核验异常帧地址、长度和 EXC_RETURN，拒绝无效堆栈 |
| 保存位置 | 当前 reset_diag 使用 RTC BKP13 起的备份字；D1 扩展需设计版本/CRC/提交规则，不能占用现有备份寄存器 |
| .noinit | 链接器显式 NOLOAD、启动零化排除，并核验 Bootloader 不覆盖；温复位保留不代表断电保留 |
| 内存数据 | 适配 ram_watermark、硬堆预留、分配失败计数；不能复制参考工程的 16 KiB 栈假设或以 0 冒充已测数据 |
| 固件身份 | 用当前发布身份映射 image_code，替代原包 FW_OTA_VERSION_CODE；PC/LR 必须与故障时版本匹配 |
| 日志发送 | 借用现有 1,024 B service_workspace 所有权，不再新增常驻日志数组；测试原 LOG 与两个扩展的最大长度、截断和发送失败 |
| 平台解释 | 保持 schema1 字段顺序、未知码和证据有效位；看门狗复位不能直接推断“程序死循环” |
| 掉电/事务 | 保留结构需要发布顺序和中断/复位切点测试；CRC 只能识别损坏，不能替代全部掉电语义 |

不引入参考工程的定时维护重启策略，该策略不属于诊断能力。异常路径应只做最小上下文交接，复杂格式化、发送及持久化留到重启后的前台。

优先级建议：先腾出资源后接入 D0 的启动/复位原因与已有内存水位；再加 D1 的故障前采样和版本绑定。完整 D1 需要同步 Bootloader/链接器保留区验证，不能仅改 App 主循环。

## 6. 平台与实机验收

平台未确定，本轮未修改本地 test-platform。真实轨迹平台需要验证：

- 保留原始设备时间、接收时间、补报类型和原始里程字段；历史点与实时点不能按错误时间混排后解释成累计里程回退。
- 历史报文缺少 0x01 时标为里程缺失，不用接收时最新里程填充旧点。
- 追查第129行原始 0x0200/0x0704 字节、完整 BCD 日期与 0x01，结合该时刻设备日志判断 124 km 的来源；现有表格不能补足这些证据。

需要实机/HIL 验证的最小项目：

1. 启动记录 LSI Hz、校准结果和睡眠配置；在常温及温度变化下对照参考时钟，覆盖 8 小时无定位及跨午夜。校准失败时确认有限等待与回退日志。
2. 有网/无网睡眠后验证 NTP 6 小时触发及 5 分钟重试；不改定位有效位，不覆盖原采集 UTC。
3. 静止、振动、弱信号、正常起步、传感器失效分别回放并抓报文；确认无定位/静止不会被本轮修改放行里程。
4. 离线、入库失败、复位后补报，逐字节核对历史时间和里程；混合旧 34 字节与新 40 字节记录通过真实平台解析。
5. 运行 OTA、盲区回放及配置写入等高栈路径，测量栈水位、堆间隙和看门狗；当前 RAM 仅满足静态审计门槛，没有为新增功能预留空间。
