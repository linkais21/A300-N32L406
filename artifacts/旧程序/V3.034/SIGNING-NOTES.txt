V3.034 - SWD-only image.  Fixes the nested-read defect that V3.032 relocated
instead of removing.

WHAT WAS WRONG IN V3.032
------------------------
V3.032 adopted the A300-N32G452 arrangement (record the recv URC, read from the
main loop) but gated it on a flag, s_qird_service_context, that was held true
for the WHOLE read pass:

    ec800m_process():
        s_qird_service_context = true;
        process_urc("+QIURC: \"recv\",1");   /* reads 12 x 256 bytes here */
        s_qird_service_context = false;

    process_urc() recv branch:
        if (!s_qird_service_context) { record the channel; return; }
        ... read ...

qird_collect_payload() dispatches lines it does not recognise through
process_rx_line() -> process_urc().  A "+QIURC: \"recv\"" arriving mid-collection
therefore found the flag still set, skipped the record-and-return path, and
started a nested read.  The inner read refills the shared s_at_resp; the outer
read then publishes a pointer into it together with its own length, so the
caller stores the inner chunk at the outer offset.  One chunk written twice,
one lost, byte count unchanged.  The guard was live exactly when it was needed
and open exactly when the hazard existed.

Field evidence (19:31 log, V3.032 pulling V3.035's predecessor):
  - download reached 100% (105784/105784) with no abort, digest still wrong
  - [4G-RX] ch=1 qird_lag=768 have_read=16563 acct=17331   (3 x 256 surplus)
  - [4G-RX] ch=1 qird_drained=283 printable=124 resid_hdrs=1/1
  - qird_head dumped mid-stream binary (08 fd 6a 00 08 ca cf 01 ...), i.e. the
    tail of a body that was left unread, followed by a whole stranded response

THE FIX
-------
The read pass is now a function of its own, qird_service_channel(), called
directly from ec800m_process().  process_urc()'s recv branch is unconditionally
"set the bit in s_tcp_qird_pending_mask and return" - there is no context flag
and no path by which a URC can start a socket read.  This is the shape the
working N32G452 firmware has always had
(fota-platform/A300-N32G452/app/src/ec800m.c: s_pending_recv_mask, line 75
comment "Preserve their meaning without recursively running QIRD (which would
overwrite the caller's AT response)").

Retained from earlier versions:
  - s_qird_pass_active (V3.030) still blocks process_deferred_urc_one() during a
    pass - second line of defence, no longer the only one
  - the AT+QIRD=<ch>,0 have_read cross-check (V3.028) as post-hoc diagnosis

WHAT TO LOOK FOR IN THE NEXT LOG
--------------------------------
  - digest matches; install proceeds past stage=sha256
  - qird_drained / qird_head must not appear at all during the download
  - qird_lag may still appear once at a small steady value (modem reporting lag,
    benign); it must not grow
  - [4G-RX] ch=1 event=recv appears once per pass, i.e. before each run of ~12
    qird=256 lines, never in the middle of one
