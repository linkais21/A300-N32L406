# A300_406 优化试机包：V3.038 烧录 → V3.039 OTA

生成日期：2026-09-13。目标硬件：A300-T9 / N32L406CBL7，128 KiB Flash、24 KiB SRAM。
两版包含相同业务代码及当前工作树优化：构建依赖/资源门禁、堆边界、相同 GPS 坐标
避免重复里程计算、AGNSS 会话快照读取。版本不同用于验证完整 OTA 升级链。

**仅供本次实机/HIL 测试。RAM/release-gate 未通过，不能视为正式发布版本。**
两版 App 均为 105,776 B，分区剩余 720 B；静态 RAM 17,904 B，已知调用链栈帧
2,984 B，扣除这两项后余量 3,688 B，低于 4,096 B 要求，且堆/异常/完整栈证据
尚未闭合。该失败状态保留在各版本 manifest 和构建日志中，未修改门禁阈值。

## 使用文件

| 用途 | 文件 | 大小 | 地址/平台参数 |
|---|---|---:|---|
| 首先 SWD 烧录 | `SWD-Combined-V3038.bin` | 130,352 B | **0x08000000** |
| 同一烧录镜像的 HEX 格式 | `SWD-Combined-V3038.hex` | 366,683 B | 文件已携带地址 |
| 随后 OTA 上传 | `OTA-A300-406-V3039.bin` | 105,808 B | **型号 A300-406；版本号 3039；显示 V3.039** |

1. 使用现有 N32L406 烧录工具，选择 Combined BIN 或 HEX 其中一个烧录并回读校验。
   Combined 已包含当前修正公钥的 Bootloader（12,312 B）、填充区和 V3.038 App；
   App 在镜像内偏移 0x6000，不要将整个 Combined 写到 0x08006000。
2. 保留外部 SPI Flash 和已有设备配置；不需要清空设备身份、JT808 主/备服务器或
   OTA 地址。若工具提供整片/配置清空选项，不把它作为本次测试必需步骤。
3. 先完成 V3.038 上线与定位检查，再把 OTA 文件上传到现有 FOTA 平台，为测试设备
   创建 V3.039/3039 升级任务。OTA 文件为 32 B A300 包头 + App，平台上传流程生成
   分离式签名；本地文件不是 Combined，也不是裸 App。
4. 配置任务后按现有流程触发开机检查。未在本轮上传、创建任务、远程重启或烧录。

## 上线和定位验收

- 调试串口 **115200 / 8N1**，保存上电到稳定联网的完整日志；先确认启动版本
  V3.038，OTA 后确认 V3.039，签名 key 标识为 `FOTA-PLATFORM-P256`。
- 确认 4G ready、JT808 注册/鉴权成功，平台显示在线；检查 0x0107 终端信息中的
  型号/版本，确认未发生持续重连或重复重启。若已保存有效鉴权码，可以直接鉴权。
- 室外 GNSS 定位后检查平台 0x0200 的定位有效位、经纬度、时间及合理性；未定位时
  不应把旧坐标报为有效实时定位。观察静止/移动及配置上报周期，检查里程无异常跳变。
- 检查每分钟 `[HEALTH]` 日志中的 `HEAP_USED / STK_PEAK / RAM_GAP`，记录最坏值；
  同时观察串口丢帧、定位中断、看门狗/HardFault 和主循环阻塞线索。
- OTA 期间观察 `accept version=3039`、下载 105808/105808、`authorized`、`pending`、
  `reboot` 和目标版本启动。TRIAL App 运行约 30 秒后会提交确认并主动复位一次，
  随后应稳定运行 V3.039；不能持续回退旧版或反复重启。
- OTA 后再次验证上线、定位、上报和设备配置保留。AGNSS 分块输出、真实 SPI 时序、
  DWT 周期以及实际 Flash/断电恢复仍需要实机/HIL 验证。

日志对外分享前请脱敏 IMEI、手机号、服务器密钥和位置。一次试机通过不代表 RAM
上界已证明，也不能替代完整发布验收。
