# A300 完整烧录与产测样机包（2026-09-17）

目标：A300-T9 / N32L406CBL7。用于本次产测联调，不适用于 A700 MCU。
本包来自当前 main 工作树，包含已合入标准源码的数学/日志/毫米量化优化和产测接口；不是另建产品分支。
App 占用 100820 B，剩余 5676 B。固件内部版本仍为 V3.054，必须用本包文件及 SHA256 区分旧 V3.054。

## 烧录哪个文件

- 推荐 `SWD-Combined-N32L406CBL7.hex`：完整 Bootloader + 出厂初始化标记 + App，HEX 自带地址。
- 或 `SWD-Combined-N32L406CBL7.bin`：同一镜像，烧录起始地址 **0x08000000**。
- 两者选一个，不需要重复烧录。diagnostics 中的 App.bin 只是诊断用分区文件，不能当整片镜像烧到 0x08000000。
- 没有 OTA 包；不要把 Combined 文件上传到 OTA 平台。

## 样机烧录步骤

1. 确认 MCU 为 N32L406CBL7；使用适配该 MCU 的现有 SWD 烧录器及工具，连接 SWDIO、SWCLK、GND 和目标板参考电压。
2. 本包为出厂初始化镜像。烧录前保存需要保留的设备参数；首次启动会清除外部 Flash 的配置双槽、BCR、FOTA 断点及授权状态，随后需要重新写入参数。不要当作保留现场参数的升级包。
3. 在烧录软件中选择目标芯片，执行 MCU 内部 Flash 擦除，烧录上述 HEX，或选择 BIN 并设置 0x08000000；执行写后校验，然后复位。
4. 接调试 UART：115200、8N1、3.3V TTL、共地。设备 PA9(TX) 接适配器 RX，PA10(RX) 接适配器 TX。观察启动日志，等待初始化完成。
5. 发送 `FACTORYCAP#`，应得到 `VER=1,ACC=1,GSENSOR=1,VOLTAGE=1,RELAY=1,TTS=0,RS485=0,SOS=1,GNSS=1=Success!`。无正确响应时先检查镜像、接线及启动日志。

## 与生产测试工具联调

原现场 `bin/A300ProductionTester.exe` 为旧工具；其完整兼容性尚未确认，不能据本包宣称全部可用。用户正在确认实际使用的 EXE。
当前已完成跨端协议自动验证的是同一工具源码生成的 V1.6.0 候选：
`生产测试工具/A300ProductionTester/build-releases/V1.6.0-production-candidate/A300ProductionTester.exe`。
本烧录包不替换现场 EXE、订单、配置或记录，也不宣称已完成 A300/A700 通用工具适配。

使用 V1.6.0 候选验证时：

1. 连接天线、SIM、测试电源和继电器治具；使用板级治具，不接真实车辆负载。
2. 启动 EXE，选择调试串口。新建测试订单，版本设 V3.054；核对服务器、APN、型号、终端信息和电压门限，禁止直接沿用未核实的默认服务器配置。
3. 先读取设备信息，然后按需“写入并测试”。TTS、RS485 跳过，不计为通过。
4. GNSS 阶段保持 ACC ON；ACC 阶段按提示完成两次通断；震动阶段晃动整机；SOS 阶段先释放，再按下保持规定时长。
5. 继电器阶段在治具上观察两轮 LOW/HIGH；真实观察到外部负载动作才确认通过，MCU 响应不等于触点通过。
6. 检查逐项结果和 records 中 CSV。失败、超时、未测试不能改判为通过。保留启动日志及失败项响应用于分析。
