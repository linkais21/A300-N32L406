# A300 V1.5.0 联调 Fix6：迁入历史 A300 继电器 GPIO 驱动处理

继续使用原 V1.5.0 EXE。保留 Fix5 已通过现场 GPS 测试的华大配置/解析，以及此前 APN、SIM 6F、盲区、编译时间等改动。没有创建分支或执行烧录。

## 对照与修改

用户确认两个项目电路相同；12V 继电器接线确认，工具 RELAY 测试与平台命令均无吸合声，CRT_EXT 测量电压未变化。工具 PASS 不能代替外部线圈/触点验收。

只读对照 fota-platform/A300-N32G452/app/src/relay.c：原 A300 在每次命令时开启 GPIOA 时钟并重配置 PA11 推挽输出。当前 N32L406 原先只在启动时配置。将该处理迁入当前驱动，使用 N32L40x 的 GPIO_Slew_Rate、GPIO_Current、GPIO_Pull API；先预装目标输出锁存值再启用推挽，避免瞬间驱动旧值。GPIO 重配置在主循环完成；1ms ISR 的产测到期恢复仍仅清输出、更新状态。

接口语义冲突已适配：历史 A300 relay_set(true) 是供油，当前 true 是断油。因此保持当前上层协议、调用参数及 PA11 高=断油、低=恢复。没有照搬旧 API 的布尔值。

历史 A300 另有 10 秒低速等待及直接断油模式；本次迁移 GPIO 驱动，不引入绕过安全条件的直接模式或新的延迟执行状态机。当前远程断油仍要求有效 GNSS、有限非负速度且低于 20km/h；不满足即拒绝。恢复不限定位。产测脉冲最多 3 秒，工具可提前恢复；产测与远程请求互斥逻辑保留。

执行断油/恢复时新增串口诊断：

```
[RELAY] CUT=1 ODR=1 PAD=1 TEST_MS=3000
[RELAY] CUT=0 ODR=0 PAD=0 TEST_MS=0
```

CUT 为软件请求，ODR 为输出锁存，PAD 为 MCU 引脚读回；均不能证明 Q17、线束、继电器触点状态。现场根因尚未确认为引脚模式被覆盖，迁移通过主机故障注入验证，但不能宣称已解决现场不吸合。

## 使用步骤

1. 保存参数，烧录 SWD-Combined-N32L406CBL7.hex 并校验/复位；使用 BIN 时地址 **0x08000000**。完整镜像首次启动会重置配置/升级状态，重新写入参数。不能把完整 BIN 写到 App 的 0x08006000。
2. 保持已确认的 12V 线圈供电/共地接线，在原工具单独测试 RELAY。确认两次真实吸合及恢复，测 CRT_EXT 是否在脉冲期间接近 0V。不以自动 PASS 作为触点证明。
3. 平台下发需区分发送成功、设备 ACK 成功和实际断开。当前支持 0x8105 单字节 0x64 断油/0x65 恢复，保持既有短信/文本 RELAY 安全路径。若无动作，应记录实际平台下发帧与设备应答，不根据 UI 文案猜测指令格式。
4. 若仍无动作，保存 [RELAY] 日志和 PA11/CRT_EXT 测量结果；不要反复更换极性。产测自动恢复输出，测量需能捕捉短脉冲。

G-sensor 静止误通过的问题仍未关闭：原 EXE 阈值 30 小于已观察到的变化 52，不能伪造 XYZ 或 INT 让工具等待。保留只读采集脚本 capture_sensor_relay_diag.ps1，用于静置 10 秒/晃动 10 秒/静置 10 秒采样；当前尚未收到该采样日志。
