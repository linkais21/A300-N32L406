# V3.051 Flash 复核

本报告是容量分析，独立于 ponytail 的复杂度审核。没有应用源码简化建议，没有改 C/C++、链接布局、功能宏、签名校验或协议。本轮只新增测试构建、审核证据及交付文件。

## 可复核结果

工具链：ARM GNU Toolchain 14.3.1。App 原点 0x08006000，容量 106496 字节；Bootloader 固定预留 24576 字节，其中 0x08005800 有工厂初始化记录页。

| 同一当前源码 | ELF 文件字节 | HEX 文件字节 | BIN/Flash 跨度字节 |
| --- | ---: | ---: | ---: |
| 原有 -Os / LTO / GC 配置 | 161192 | 294473 | 104672 |
| 新增 -finline-limit=64 | 161208 | 294158 | 104560 |
| 差值 | +16 | -315 | -112 |

本轮独立目录全量重建确认 BIN=104560，App 剩余 1936 字节。前次正式提供的 V3.050 测试包 App 为 104656 字节，所以跨版本只小了 96 字节；与同源码基线比较的 112 字节不能混为一谈。ELF 带符号，HEX 是带地址的文本格式，都不能直接用磁盘大小判断 MCU Flash 占用。

主 Makefile 已有 -Os、-flto=1、-flto-partition=one、-ffunction-sections、-fdata-sections、--gc-sections、nano.specs、-g0。Cortex-M4/Thumb/fpv4-sp-d16/hard-float 不变，签名模块的 -fno-lto 审计边界不变。前一轮 11 组参数试验只有小幅收益；不是漏开基础优化。

## 最终映像中的实际占用

MAP 输入节归属统计（不是可删除空间，排除填充，不能与字符串区重复相加）：libm 8252 字节、libgcc 2676 字节、libc_nano 3596 字节、micro-ecc 3488 字节、签名包装与公钥 112 字节。详细数据见 validation/map-contributors.json。

App 的 LTO 字符串区为 10255 字节，其中 144 条以方括号标签开头的字符串合计 6423 字节（含结尾零）；标签筛选只是诊断文本规模估算，不代表全部可以删除。整个 .rodata 为 12920 字节，已包含上述字符串、常量与部分库数据。

1. 数学计算是较大的后续评估方向：src/mileage.c:39 使用 double Haversine，拉入 sin/cos/atan2/sqrt 及参数归约函数。M4 的当前 FPU 是单精度，双精度仍需软件支持。不能直接把经纬度改 float，也不能启用 -ffast-math 或 -fsingle-precision-constant 来假装无行为变化；它们可能改变米级距离、漂移过滤和里程阈值。若后续允许源码优化，应先冻结误差容限，做跨纬度/经度边界/小位移回放，再测 BIN。8252 字节是当前库贡献，不是保证可全部回收。
2. 日志文本是第二个候选：删除、缩短或按等级禁用现有日志会改变可观察行为及 HIL 证据。本轮保留。若要求输出完全一致，可另行评估字典/共享格式串，但新增解码器也占 Flash，须以净收益和串口回放验收，不能直接承诺节省 6423 字节。
3. 清理 ponytail 找到的旧接口可以降低维护成本，但大部分已由 LTO/GC 消除，不能解决 KiB 级缺口。App/Bootloader 的重复 SHA 源码不在同一链接映像，合并维护也不会自动共享机器码。
4. 压缩 Bootloader 或启用其 LTO不会改变 App 起点。重新分区会牵涉向量地址、Boot/App 契约、OTA 型号/镜像边界、存量设备升级与回滚，超出当前“只调构建配置”的范围，本轮没有调整。
