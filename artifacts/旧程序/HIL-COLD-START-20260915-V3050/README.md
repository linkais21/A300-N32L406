# V3.050 首次上电修复验证版

烧录文件：**SWD-Combined-V3050.hex**。目标 A300-406 / N32L406CBL7。

HEX 已含地址。工具仅支持 BIN 时，使用 SWD-Combined-V3050.bin，地址 **0x08000000**；二者选一个即可。必须使用已验证的 N32L406CBL7 烧录配置，下载后校验并执行 reset/start。

**本次必须烧完整 Combined，不能只烧 App 或只做 OTA。** 修复在 Bootloader，OTA-A300-406-V3050.bin 仅含同版本 App，不会更新 Bootloader；随包保留供后续协议测试。

Combined 首次启动会清理配置 A/B、BCR、OTA 断点与授权记录。烧录前备份必要参数，首次成功启动后再恢复配置。之后反复上电不应重复清配置。

## 本次变化

- SPI 事务明确片选建立、保持、间隔时间，增加有界 BSY 等待，避免传输未结束就撤销片选。
- BCR 先确认 Flash ID，再读完整双槽；连续全零/无效读取和 I/O 失败均最多尝试 20 次。两次之间至少等待 100 ms 核心周期并喂狗，实际间隔因循环开销更长。
- 真正持续损坏仍拒绝启动，不将全零当作空白，不绕过 Pending、签名、回滚或工厂初始化校验。
- 新增 Bootloader 串口阶段和重试日志，失败不再只有无输出现象。持续失败最终打印 recovery 并保留现场，不无限复位。

## 连续上电测试

1. SSCOM 设置 **115200、8N1、无流控**，关闭自动发送。从烧录/上电前开始将接收内容保存到新文件。使用调试 USART1，PA9 TX 接串口 RX，共地。
2. 烧录并校验 Combined。首次启动预留 5 分钟观察工厂初始化和 App 启动，完成后再开始断电循环。此时间是排障观察窗口，不是承诺的启动耗时。
3. 成功日志应包含 `[BOOT] start=3050`、`[BOOT] factory-ready=0`、`[BOOT] select=0`、App 的 **V3.050** 横幅和 `[BOOT] ready`。蓝绿灯受网络/GNSS 状态影响，不能单独作为启动通过标准。
4. 建议至少 **50 次真实冷启动**。每次确认供电真正掉下去，再上电；板载电池、串口 VCC 或调试器不能继续维持设备供电。主测试时拔掉 SWD 调试器，串口只保留 RX/GND。用测试接线和正常电源开关，不修改电路。
5. 分组记录不同断电间隔，例如完全掉电后再等 5 秒、15 秒、60 秒。另记每次上电至 App ready 的时间、最高重试编号、灯态、电流和是否保留配置。每次等 App ready 后继续观察约 30 秒再关电；首轮工厂初始化期间不主动断电。
6. 出现 `[BOOT] bcr-data-retry=N` 或 `bcr-io-retry=N` 后最终进入 App，记为“重试恢复”；没有重试直接进入 App，记为“直接成功”。两类分别计数。
7. 如果出现 `factory-error=-1`、`reset-record-error=-1`、`recovery=-1`，或 5 分钟内没有进入 App，记为失败并停止该轮操作。**保留供电和完整日志，不立即重新上电**，以便继续读取故障现场。

记录表见 POWER-CYCLE-RESULTS.md。50 次通过只是这一批测试结果，不代表所有供电条件下已根治。
