# V3.095 里程精度修复与验证

## 问题与证据

用户确认历史设备版本为 T360-A300_406_20261015162913,V3.093。
2026-10-21 的导出轨迹共有 1312 条记录；排除未定位记录及跨日接收的补报后，
1128 条有效实时位置的球面逐点距离约 73.413 km，设备累计从 124.000 增至
194.600 km，即 70.600 km，相差约 2.813 km / 3.832%。坐标累计是稀疏轨迹估算，
不能据此判定全部差值都由本次算法缺陷产生。本文件不包含终端标识、位置或原始轨迹。

V3.093 和 V3.094 交付源码身份中 mileage.c 的 SHA256 相同，均逐段将毫米距离
整除 1000 后累加，丢弃余数。真实 C 旧实现回放 1000 段各 10.8 m，只计 10000 m。
RED 失败于预期 10800 m 的断言；原始失败日志保存在本轮 diagnostics。

历史的 2026-09-16 量化草案明确采用逐段整米截断、不带余数；这与本轮用户要求
优化持续少计的目标冲突。本轮按用户新要求替代该项旧策略，其余量化/防漂/拒绝边界
保持不变，未将旧草案的误差结论当作新实现的结论。

## 实现及兼容边界

仅在现有接受分支（500 < dist_mm < 1000000 且已通过静止/低速过滤）内：

1. 将本段毫米数与上次已接受余数相加。
2. 满一米的部分进入现有 cfg_add_mileage；不足一米仅保留在 RAM。
3. 余数范围 0～999 mm，单次中间和不超过 1000998，uint32_t 不溢出。
4. 没有完整一米时不调用 cfg_add_mileage，避免仅小数变化就置脏或触发保存。

停车/失效定位不清除已赚取的余数；静止坐标、异常跳点、低速拒绝点不获得余数。
原静止释放首点仅重建基准、不回填停车漂移，原重复坐标短路仍保留。
原 <=500 mm 拒绝、>=1000 m 跳点拒绝、低速阈值及基准推进规则没有改动。
本修复没有取消这些校验，不按固定百分比扩大距离，不重建既往少计里程。

设备配置、Flash 布局/事务、JT808 0x01 的 0.1 km 单位不变。
余数不进入持久记录，因此一次复位可丢失不足一米的余数；原来十分钟周期保存、
失败重试及部分掉电/复位路径的未保存整米损失仍存在，不宣称断电零回退。
正常 OTA 保留整米里程和配置；Combined 工厂初始化路径会重置配置。

无效定位、静止锁定/释放、拒绝跳点/短段、低速防漂以及新进程启动基线检查均通过。
静止判定在此精度测试中为可控夹具；test_stationary_mileage.py 同时编译真实
GPS report filter 和 mileage.c 验证实际过滤集成，test_gps_report_wire.py 验证上报链路。
已有量化测试逐案例清除新余数，更新 0.5006 m 不再发起零米累加的预期。
其他距离/接受边界断言未放宽。

最终命令、脚本清单、退出码、输入源码哈希见交付 diagnostics/host-results.json、

## 需要实机/HIL 验证

新镜像尚未烧录或执行真实 OTA。需同路线独立参考里程对照、长时间静止、低速及反复起步、
转弯、无定位恢复、网络等待、重启/断电等场景，记录起止原始里程与实测误差。
主机回放与 ARM 编译不能代替目标硬件、GNSS 数据质量、在线平台签名/安装和实测栈水位。
历史差值的其他来源（采样缺口、弯道切线、定位质量、未保存里程等）没有被本轮宣称消除。

host 测试夹具使用 NULL 却缺少 stddef.h；只补齐该头文件，保留断言与生产逻辑后通过。
保留首轮与修复记录；其余 76 项因源码、配置和依赖未变而复用已通过记录。

门槛 4096 B；相对本轮开始的 V3.094 分别增加 32 B Flash / 4 B 静态 SRAM。
