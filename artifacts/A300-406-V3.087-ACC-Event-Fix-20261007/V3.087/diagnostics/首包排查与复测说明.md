# ACC / 震动唤醒首包排查与 V3.087 复测

用户观察平台：主业务平台。V3.086 实机串口固定快照的 SHA256、行数及唤醒序列见 serial-findings.json；原始日志仍追加。

## 实际功能场景

| 场景 | V3.086 实机日志 | 结论与边界 |
|---|---|---|
| 硬件 ACC 唤醒 | 34942、35045、35094、35143、35189 行为 SLEEP->REALTIME、logical_acc=1，随后 fallback=unfixed，主/备用均 SEND OK | 设备有发送动作，但日志无载荷及平台 ACK，不能据此认定平台已收到正确 ACC 首包 |
| Gsensor 震动唤醒 | 34987 行为 SLEEP->REALTIME、物理 ACC OFF、logical_acc=1，随后 fallback=unfixed，主/备用均 SEND OK | 共用无定位回退路径，与硬件 ACC 问题具有同一软件缺陷 |
| 主平台观察 | 用户确认唤醒后没有立即显示/上报 ACC ON | 与发送日志不一致，需要新包字段诊断及主平台原始收包对账 |

明确的软件缺陷：休眠 0200 使用推进中的事件时间，唤醒首包却调用 gps_get_last_trusted_location 恢复旧定位采集时间。
因此首包时间可以早于已经发送的休眠包。主平台是否据此过滤尚未取得原始收包/过滤记录，属于待实机/平台验证的影响假设。

## 修复行为

状态切换首包及防抖结束后的状态补发使用新事件接口：无有效定位时使用可信旧坐标与推进中的事件时间，ACC 位来自逻辑状态，当前定位位仍为 0。
首包不等待搜星，不将旧坐标伪装为实时定位。普通无定位包和 0201 查询继续保留采集时间；已有盲区事务在重试时保留原始时间和 ACC。
本轮产品代码只涉及 src/main.c、src/jt808.c、include/jt808.h，另同步版本身份、门禁及配套工程验证入口。
原有 ACC 500 ms 防抖、短时间反转抑制及震动 6 秒确认条件保留。

## 新版本实机验收

尚未烧录 V3.087，所有下列场景均需要实机/HIL 验证。

1. 核对启动版本 V3.087，主平台鉴权在线后让设备进入休眠。
2. 用硬件 ACC 唤醒；从防抖确认开始核对首包发送及 `[808-EVENT]`。预期 acc=1、fix=0（未定位时）、ts 为当前事件的本地 BCD 时间、tx=0（主通道发送成功）。tx 不是主平台业务 ACK。
3. ACC 物理 OFF，再休眠并持续有效震动；确认进入 REALTIME 后，同样应有 ACC ON 未定位首包，随后搜星成功再补有效定位包。
4. 主平台检查原始 0200 的状态 bit0、bit1、时间及到达时刻，区分接收、数据库入库和界面显示。若原始包正常但不更新，核对未定位包与历史时间过滤规则。
5. 验证 ACC OFF、短时抖动、反向切换及再次休眠，确认不会重复首包或改变防抖。
6. 验证断网时存储并恢复补报；重试不能改变已存事件的时间或 ACC。

诊断说明：t 为发送尝试结束时 MCU 毫秒计数；ts 是实际 0200 中的本地 BCD 时间 YYMMDDhhmmss；acc/fix 是实际编码状态位；tx 是广播发送结果。
没有坐标/设备标识字段。无 GNSS、无网络时间且没有可信旧时间时，不能制造正确民用时间。
